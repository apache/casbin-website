Meningkatkan **Casbin** (Go) dari v2 ke v3: Panduan Migrasi Lengkap

1 Februari 2026 · Bacaan 1 minit
Yang Luo
Creator of Casbin

Jika anda menjalankan Casbin v2 dalam persekitaran pengeluaran dan tertanya-tanya tentang laluan peningkatan ke v3, panduan ini adalah untuk anda. Kami akan merangkumi segala yang perlu anda ketahui tentang peralihan tersebut, daripada memahami apa yang berubah hingga melaksanakan migrasi pengeluaran yang selamat.

Apa Yang Berubah dalam v3?​

Khabar baik: v3 terutamanya ialah perubahan laluan modul dengan keserasian mundur penuh. Logik pengesahan teras, API, dan fungsi kekal tidak berubah. Ini adalah keputusan yang disengajakan untuk meminimumkan gangguan sambil mengikuti konvensyen versi semantik Go.

Perubahan Utama: Laluan Modul​

Satu-satunya perubahan memecahkan (breaking change) dalam v3 ialah laluan modul Go:

// v2
import "github.com/casbin/casbin/v2"

// v3
import "github.com/casbin/casbin/v3"

Itu sahaja. Dasar, model, dan logik kod sedia ada anda tidak perlu diubah. Migrasi adalah mekanikal: kemas kini pernyataan import dan fail go.mod anda.

Mengapa Keluarkan v3?​

Anda mungkin tertanya-tanya mengapa mengeluarkan versi major baharu hanya untuk perubahan laluan import. Jawapannya ialah versi semantik. Sistem modul Go menggunakan nombor versi major dalam laluan import (/v2, /v3, dll.). Ini membolehkan pelbagai versi major wujud serentak dalam pokok kebergantungan yang sama, yang penting untuk aplikasi besar dengan banyak kebergantungan.

Dengan mengeluarkan v3, kami telah:

  • Menyelaras dengan versi import semantik Go
  • Membolehkan migrasi berperingkat dalam graf kebergantungan yang kompleks
  • Menetapkan pentas untuk penambahbaikan masa hadapan tanpa mengganggu pengguna v2 sedia ada

Apa Yang Kekal Sama?​

Semua yang lain. Serius.

  • Semua API kekal identik - Enforce(), AddPolicy(), GetAllRoles(), dan setiap kaedah lain berfungsi tepat seperti sebelumnya
  • Sintaks model dan dasar tidak berubah - Fail model .conf dan fail dasar .csv sedia ada anda berfungsi tanpa pengubahsuaian
  • Antara muka Adapter tidak berubah - Kaedah persist.Adapter adalah sama; adapter hanya perlu keluaran yang dibina terhadap laluan modul v3
  • Ciri prestasi - Tiada regresi atau penambahbaikan prestasi; ia adalah enjin yang sama
  • Integrasi perantara (middleware) - Perantara berfungsi dengan cara yang sama setelah ia mengimport versi major yang sama dengan enforcer anda

Ciri Baharu dalam v3​

Sejak pelepasan v3.0.0 pada Disember 2025, beberapa ciri baharu telah ditambah:

v3.7.0+: Integrasi Logger Dipertingkatkan​

Anda kini boleh mengintegrasikan logger tersuai ke dalam operasi penguatkuasaan teras Casbin dan pengurusan dasar, menyediakan keterlihatan (observability) yang lebih baik:

enforcer.SetLogger(yourCustomLogger)

v3.8.0+: API GetAllUsers()​

API baharu untuk membezakan pengguna daripada peranan:

users, err := enforcer.GetAllUsers()

Ini amat berguna dalam sistem RBAC di mana anda perlu menyenaraikan pengguna sebenar secara berasingan daripada definisi peranan.

v3.9.0+: Pengesanan Kitaran Terbina Dalam​

Enforcer kini termasuk pengesanan automatik kitaran dalam hierarki peranan, mencegah gelung tak terhingga:

// Automatically detects and prevents circular role assignments
enforcer.AddGroupingPolicy("alice", "admin")
enforcer.AddGroupingPolicy("admin", "alice") // Will be detected as a cycle

v3.10.0+: API Explain() untuk Wawasan Pengesahan Didorong AI​

Ciri terkini memanfaatkan API LLM untuk menjelaskan keputusan pengesahan dalam bahasa semula jadi:

enforcer.SetAIConfig(casbin.AIConfig{
    Endpoint: "https://api.openai.com/v1/chat/completions",
    APIKey:   os.Getenv("OPENAI_API_KEY"),
    Model:    "gpt-4",
})

explanation, err := enforcer.Explain("alice", "data1", "read")
// e.g. "Alice can read data1 because she has the 'reader' role..."

Ini amat bernilai untuk menatalah (debugging) dasar kompleks dan membantu pihak berkepentingan bukan teknikal memahami keputusan pengesahan.

Strategi Migrasi​

Untuk Projek Baharu​

Mudah: hanya gunakan v3 dari awal.

go get github.com/casbin/casbin/v3
import "github.com/casbin/casbin/v3"

Untuk Projek v2 Sedia Ada​

Proses migrasi melibatkan tiga langkah:

Langkah 1: Kemas Kini go.mod Anda​

go get github.com/casbin/casbin/v3
go mod tidy

Langkah 2: Kemas Kini Kenyataan Import​

Cari dan ganti semua import Casbin merentas pangkalan kod anda:

# Using sed on Unix/Linux/Mac
find . -type f -name '*.go' -exec sed -i 's|github.com/casbin/casbin/v2|github.com/casbin/casbin/v3|g' {} +

# Or manually in your editor
# Find: github.com/casbin/casbin/v2
# Replace: github.com/casbin/casbin/v3

Langkah 3: Kemas Kini Import Adapter (Jika Berkenaan)​

Sebuah adapter melaksanakan persist.Adapter daripada satu versi utama tertentu, kerana model.Model dalam casbin/v2 dan casbin/v3 ialah jenis Go yang berbeza. Oleh itu, enforcer v3 memerlukan pelepasan adapter yang mengimport github.com/casbin/casbin/v3. Periksa go.mod adapter tersebut:

// Example: the PostgreSQL adapter already depends on casbin/v3
import pgadapter "github.com/apache/casbin-pg-adapter"

// The file adapter is built in and ships with each major version

Jika adapter anda belum dikemas kini, kekal pada v2 untuk perkhidmatan tersebut sehingga ia dikemas kini, atau buka isu di repositori adapter tersebut.

Pelan Pengunduran​

Jika anda perlu melakukan pengunduran:

  1. Tahap Kod: Pulihkan perubahan import (gunakan kawalan versi)
  2. Tahap Kebergantungan: go get github.com/casbin/casbin/v2@latest
  3. Penyebaran: Gunakan proses penyebaran standard anda untuk memulihkan

Keindahan migrasi ini ialah pengunduran adalah mudah - hanya pulihkan perubahan import dan sebarkan semula.

Adakah Saya Perlu Memigrasikan Pangkalan Data Dasar Saya?​

Tidak. Data dasar sedia ada anda kekal tidak berubah. Dasar disimpan sebagai rentetan ringkas (subjek, objek, tindakan, dll.) dan tiada kebergantungan pada versi Casbin.

Menguji Migrasi Anda​

Pengujian Automatik​

Ujian sedia ada anda harus lulus tanpa pengubahsuaian:

func TestPolicyEnforcement(t *testing.T) {
    // This test works identically in v2 and v3
    e, _ := casbin.NewEnforcer("model.conf", "policy.csv")
    
    ok, _ := e.Enforce("alice", "data1", "read")
    if !ok {
        t.Error("Expected alice to have read access to data1")
    }
}

Pengujian Integrasi​

Perisian antara muka yang mengambil *casbin.Enforcer terikat kepada satu versi utama dengan cara yang sama seperti adapter. Jika perisian antara muka anda masih mengimport casbin/v2, memanggil enforcer secara langsung hanyalah beberapa baris:

// Example with Gin
import (
    "net/http"

    "github.com/casbin/casbin/v3"
    "github.com/gin-gonic/gin"
)

func Authorizer(e *casbin.Enforcer) gin.HandlerFunc {
    return func(c *gin.Context) {
        ok, err := e.Enforce(c.GetString("user"), c.Request.URL.Path, c.Request.Method)
        if err != nil || !ok {
            c.AbortWithStatus(http.StatusForbidden)
            return
        }
        c.Next()
    }
}

Pengujian Beban​

Jalankan ujian beban standard anda terhadap binaan v3. Ciri prestasi harus sama dengan v2.

Pengesahan Dasar​

Bandingkan penilaian dasar merentas versi:

# Export policies from v2
# Load into v3
# Run test cases against both
# Compare results

Jika anda melihat sebarang perbezaan, kemungkinan besar itu adalah pepijat - sila laporkannya!

Perangkap Umum​

Perangkap 1: Kebergantungan Campur v2/v3​

Masalah: Sesetengah kebergantungan menggunakan Casbin v2, yang lain menggunakan v3, menyebabkan konflik.

Penyelesaian: Binaan itu sendiri adalah baik: sistem modul Go menganggap v2 dan v3 sebagai pakej berasingan, jadi kedua-duanya boleh berada dalam pokok kebergantungan yang sama. Apa yang anda tidak boleh lakukan ialah menghantar enforcer v3 ke pustaka yang mengharapkan enforcer v2. Kekalkan enforcer, adapternya, dan perisian antara mukanya pada versi utama yang sama.

Perangkap 2: Ketidakpadanan Versi Adapter​

Masalah: Menggunakan adapter v2 dengan Casbin v3 (atau sebaliknya).

Penyelesaian: Ini muncul sebagai ralat kompilasi, bukan kejutan masa jalan. Periksa versi utama Casbin mana yang diperlukan oleh go.mod adapter dan gunakan pelepasan yang sepadan dengan enforcer anda.

Perangkap 3: Lupa Pakej Dalaman​

Masalah: Mengemas kini import aplikasi utama tetapi lupa pakej dalaman atau alatan.

Penyelesaian: Gunakan go mod graph dan go mod why untuk mencari semua kebergantungan Casbin:

go mod graph | grep casbin

Perangkap 4: Isu Kompilasi Adapter Tersuai​

Masalah: Penyesuai tersuai tidak dapat dikompil selepas naik taraf.

Penyelesaian: Antara muka penyesuai tidak berubah, jadi ini mencadangkan isu import. Pastikan semua import Casbin dalam penyesuai anda menggunakan v3:

import (
    "github.com/casbin/casbin/v3"
    "github.com/casbin/casbin/v3/persist"
)

FAQ​

Q: Adakah v2 masih diselenggara?​

Setakat penulisan ini, v2 menerima pembetulan pepijat kritikal, tetapi ciri baharu dibangunkan untuk v3. Rancang untuk bermigrasi dalam masa 6-12 bulan akan datang.

Q: Bolehkah saya bermigrasi secara berperingkat dengan mempunyai beberapa perkhidmatan pada v2 dan yang lain pada v3?​

Boleh! Malah mereka boleh berkongsi pangkalan data dasar yang sama. Ini adalah salah satu faedah daripada perubahan minimum dalam v3.

Q: Adakah perantara saya (Gin, Echo, Fiber, dll.) akan berfungsi?​

Hanya jika ia mengimport versi utama yang sama seperti enforcer anda. Periksa go.mod perantara; jika ia masih pada v2, panggil Enforce() dari pengendali kecil milik anda sendiri seperti yang ditunjukkan di atas.

Q: Adakah saya perlu mengemas kini fail model .conf saya?​

Tidak. Sintaks fail model tidak berubah.

Q: Adakah saya perlu mengemas kini fail dasar .csv saya?​

Tidak. Format fail dasar tidak berubah.

Q: Bagaimana pula dengan WatcherEx, FilteredAdapter, dan antara muka lain?​

Semua antara muka kekal tidak berubah. Jika kod anda melaksanakan antara muka ini, tiada pengubahsuaian diperlukan (selain daripada laluan import).

Q: Kesan prestasi?​

Tiada. v3 menggunakan enjin penilaian yang sama seperti v2.

Q: Bolehkah saya menggunakan v3 dengan Go 1.16?​

Periksa go.mod dalam repositori Casbin v3 untuk versi Go minimum yang disokong. Secara amnya, disarankan untuk menggunakan versi stabil Go terkini.

Selamat naik taraf!
