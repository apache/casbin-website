Atualizando o Casbin (Go) da v2 para a v3: Um Guia Completo de Migração

1 de fevereiro de 2026 · Leitura de 9 min
Yang Luo
Creator of Casbin

Se você está rodando o Casbin v2 em produção e se pergunta sobre o caminho de atualização para a v3, este guia é para você. Cobriremos tudo que você precisa saber sobre a transição, desde entender o que mudou até executar uma migração segura em produção.

O que mudou na v3?​

A boa notícia: a v3 é principalmente uma mudança de caminho de módulo com compatibilidade total com versões anteriores. A lógica central de autorização, APIs e funcionalidades permanecem inalteradas. Essa foi uma decisão intencional para minimizar interrupções enquanto seguimos as convenções de versionamento semântico do Go.

A Principal Mudança: Caminho do Módulo​

A única quebra de compatibilidade na v3 é o caminho do módulo Go:

// v2
import "github.com/casbin/casbin/v2"

// v3
import "github.com/casbin/casbin/v3"

É isso. Suas políticas existentes, modelos e lógica de código não precisam mudar. A migração é mecânica: atualize as declarações de import e seu arquivo go.mod.

Por que lançar a v3?​

Você pode se perguntar por que lançar uma nova versão principal apenas por uma mudança de caminho de import. A resposta é o versionamento semântico. O sistema de módulos do Go usa o número da versão principal no caminho de import (/v2, /v3, etc.). Isso permite que múltiplas versões principais coexistam na mesma árvore de dependências, o que é crucial para grandes aplicações com muitas dependências.

Ao lançar a v3, nós:

  • Alinhamos com o versionamento semântico de imports do Go
  • Habilitamos migração gradual em grafos de dependência complexos
  • Preparamos o terreno para futuros aprimoramentos sem quebrar usuários existentes da v2

O que permaneceu igual?​

Tudo o mais. Sério.

  • Todas as APIs permanecem idênticas - Enforce(), AddPolicy(), GetAllRoles() e todos os outros métodos funcionam exatamente como antes
  • Sintaxe de modelo e política inalterada - Seus arquivos de modelo .conf e arquivos de política .csv existentes funcionam sem modificação
  • Interface de adaptador inalterada - Os métodos de persist.Adapter são os mesmos; os adaptadores só precisam de uma release construída contra o caminho do módulo v3
  • Características de desempenho - Sem regressões ou melhorias de desempenho; é o mesmo motor
  • Integrações de middleware - O middleware funciona da mesma maneira assim que importa a mesma versão principal que seu enforcer

Novos Recursos na v3​

Desde o lançamento da v3.0.0 em dezembro de 2025, vários novos recursos foram adicionados:

v3.7.0+: Integração Aprimorada de Logger​

Agora você pode integrar loggers personalizados nas operações centrais de enforcement e gerenciamento de políticas do Casbin, fornecendo melhor observabilidade:

enforcer.SetLogger(yourCustomLogger)

v3.8.0+: API GetAllUsers()​

Uma nova API para distinguir usuários de roles:

users, err := enforcer.GetAllUsers()

Isso é particularmente útil em sistemas RBAC onde você precisa listar usuários reais separadamente das definições de roles.

v3.9.0+: Detecção de Ciclos Integrada​

O enforcer agora inclui detecção automática de ciclos em hierarquias de roles, prevenindo loops infinitos:

// Automatically detects and prevents circular role assignments
enforcer.AddGroupingPolicy("alice", "admin")
enforcer.AddGroupingPolicy("admin", "alice") // Will be detected as a cycle

v3.10.0+: API Explain() para Insights de Autorização Impulsionados por IA​

O recurso mais recente aproveita APIs de LLM para explicar decisões de autorização em linguagem natural:

enforcer.SetAIConfig(casbin.AIConfig{
    Endpoint: "https://api.openai.com/v1/chat/completions",
    APIKey:   os.Getenv("OPENAI_API_KEY"),
    Model:    "gpt-4",
})

explanation, err := enforcer.Explain("alice", "data1", "read")
// e.g. "Alice can read data1 because she has the 'reader' role..."

Isso é particularmente valioso para depurar políticas complexas e ajudar stakeholders não técnicos a entender decisões de autorização.

Estratégia de Migração​

Para Novos Projetos​

Simples: use a v3 desde o início.

go get github.com/casbin/casbin/v3
import "github.com/casbin/casbin/v3"

Para Projetos Existentes na v2​

A migração envolve três etapas:

Etapa 1: Atualize seu go.mod​

go get github.com/casbin/casbin/v3
go mod tidy

Etapa 2: Atualize as Declarações de Importação​

Encontre e substitua todas as importações do Casbin em sua base de código:

# Using sed on Unix/Linux/Mac
find . -type f -name '*.go' -exec sed -i 's|github.com/casbin/casbin/v2|github.com/casbin/casbin/v3|g' {} +

# Or manually in your editor
# Find: github.com/casbin/casbin/v2
# Replace: github.com/casbin/casbin/v3

Etapa 3: Atualize as Importações do Adapter (Se Aplicável)​

Um adapter implementa persist.Adapter de uma versão principal específica, porque model.Model em casbin/v2 e casbin/v3 são tipos Go diferentes. Portanto, um enforcer da v3 precisa de uma versão do adapter que importe github.com/casbin/casbin/v3. Verifique o go.mod do adapter:

// Example: the PostgreSQL adapter already depends on casbin/v3
import pgadapter "github.com/apache/casbin-pg-adapter"

// The file adapter is built in and ships with each major version

Se o seu adapter ainda não foi atualizado, mantenha-se na v2 para esse serviço até que seja atualizado, ou abra uma issue no repositório do adapter.

Plano de Rollback​

Se você precisar fazer um rollback:

  1. Nível de Código: Reverta as alterações nas importações (use controle de versão)
  2. Nível de Dependência: go get github.com/casbin/casbin/v2@latest
  3. Implantação: Use seu processo padrão de implantação para reverter

A vantagem desta migração é que o rollback é trivial - basta reverter as alterações nas importações e redeployar.

Preciso Migrar Meu Banco de Dados de Políticas?​

Não. Seus dados de políticas existentes permanecem inalterados. As políticas são armazenadas como strings simples (sujeito, objeto, ação, etc.) e não têm dependência da versão do Casbin.

Testando Sua Migração​

Testes Automatizados​

Seus testes existentes devem passar sem modificação:

func TestPolicyEnforcement(t *testing.T) {
    // This test works identically in v2 and v3
    e, _ := casbin.NewEnforcer("model.conf", "policy.csv")
    
    ok, _ := e.Enforce("alice", "data1", "read")
    if !ok {
        t.Error("Expected alice to have read access to data1")
    }
}

Testes de Integração​

Middlewares que recebem um *casbin.Enforcer estão vinculados a uma versão principal da mesma forma que os adapters. Se o seu middleware ainda importa casbin/v2, chamar o enforcer diretamente requer poucas linhas:

// Example with Gin
import (
    "net/http"

    "github.com/casbin/casbin/v3"
    "github.com/gin-gonic/gin"
)

func Authorizer(e *casbin.Enforcer) gin.HandlerFunc {
    return func(c *gin.Context) {
        ok, err := e.Enforce(c.GetString("user"), c.Request.URL.Path, c.Request.Method)
        if err != nil || !ok {
            c.AbortWithStatus(http.StatusForbidden)
            return
        }
        c.Next()
    }
}

Testes de Carga​

Execute seus testes de carga padrão contra o build da v3. As características de desempenho devem ser idênticas às da v2.

Verificação de Políticas​

Compare a avaliação das políticas entre as versões:

# Export policies from v2
# Load into v3
# Run test cases against both
# Compare results

Se você notar alguma diferença, provavelmente é um bug - por favor, reporte-o!

Armadilhas Comuns​

Armadilha 1: Dependências Mistas v2/v3​

Problema: Algumas dependências usam Casbin v2, outras usam v3, causando conflitos.

Solução: O build em si funciona bem: o sistema de módulos do Go trata v2 e v3 como pacotes separados, então ambos podem coexistir na mesma árvore de dependências. O que você não pode fazer é passar um enforcer da v3 para uma biblioteca que espera um da v2. Mantenha o enforcer, seu adapter e seu middleware na mesma versão principal.

Armadilha 2: Incompatibilidade de Versão do Adapter​

Problema: Usar um adapter da v2 com Casbin v3 (ou vice-versa).

Solução: Isso se manifesta como um erro de compilação, não como uma surpresa em tempo de execução. Verifique qual versão principal do Casbin o go.mod do adapter requer e use uma versão compatível com seu enforcer.

Armadilha 3: Esquecer Pacotes Internos​

Problema: Atualizou as importações da aplicação principal, mas esqueceu dos pacotes internos ou ferramentas.

Solução: Use go mod graph e go mod why para encontrar todas as dependências do Casbin:

go mod graph | grep casbin

Armadilha 4: Problemas de Compilação de Adapters Customizados​

Problema: O adaptador personalizado não compila após a atualização.

Solução: A interface do adaptador não mudou, o que sugere um problema de importação. Verifique se todas as importações do Casbin no seu adaptador usam v3:

import (
    "github.com/casbin/casbin/v3"
    "github.com/casbin/casbin/v3/persist"
)

FAQ​

Q: A v2 ainda é mantida?​

Até o momento desta escrita, a v2 recebe correções críticas de bugs, mas novos recursos são desenvolvidos para a v3. Planeje migrar nos próximos 6-12 meses.

Q: Posso migrar gradualmente tendo alguns serviços na v2 e outros na v3?​

Sim! Eles podem até compartilhar o mesmo banco de dados de políticas. Este é um dos benefícios das mudanças mínimas na v3.

Q: Meu middleware (Gin, Echo, Fiber, etc.) funcionará?​

Somente se importar a mesma versão principal que o seu enforcer. Verifique o go.mod do middleware; se ele ainda estiver na v2, chame Enforce() em um pequeno handler seu, conforme mostrado acima.

Q: Preciso atualizar meus arquivos de modelo .conf?​

Não. A sintaxe do arquivo de modelo permanece inalterada.

Q: Preciso atualizar meus arquivos de política .csv?​

Não. O formato do arquivo de política permanece inalterado.

Q: E quanto ao WatcherEx, FilteredAdapter e outras interfaces?​

Todas as interfaces permanecem inalteradas. Se o seu código implementa essas interfaces, nenhuma modificação é necessária (além dos caminhos de importação).

Q: Impacto no desempenho?​

Nenhum. A v3 usa o mesmo motor de avaliação da v2.

Q: Posso usar a v3 com Go 1.16?​

Verifique o go.mod no repositório Casbin v3 para a versão mínima suportada do Go. Geralmente, recomenda-se usar a última versão estável do Go.

Boa atualização!
