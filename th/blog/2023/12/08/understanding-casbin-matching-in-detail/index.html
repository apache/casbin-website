ทำความเข้าใจกลไกการทำงานแบบละเอียดของ Casbin Matching

8 ธันวาคม 2566 · อ่าน 1 นาที
Aravinda Kumar

บทความนี้อธิบายวิธีออกแบบและนำ RBAC ไปใช้กับไลบรารี Casbin สำหรับแพลตฟอร์ม SaaS ที่มีลำดับชั้นทรัพยากรและบทบาทที่สืบทอดสิทธิ์ Casbin เป็นตัวเลือกที่มีประสิทธิภาพ

บทนำสู่ RBAC​

RBAC จำกัดการเข้าถึงตามบทบาทที่ผู้ใช้ถืออยู่ เพื่อดูว่า RBAC แบบ hierarchical ทำงานอย่างไร เราจะศึกษา RBAC ของ Azure จากนั้นนำไปประยุกต์ใช้คล้ายกันกับ Casbin

RBAC แบบลำดับชั้นของ Azure​

ใน Azure บทบาท Owner จะถูกนำไปใช้ในระดับขอบเขต (scope) ที่แตกต่างกัน หากคุณมีสิทธิ์เป็น Owner ในระดับ subscription คุณจะเป็น Owner ของกลุ่มทรัพยากรและทรัพยากรทั้งหมดภายใต้ subscription นั้น หากคุณมีสิทธิ์เป็น Owner ในระดับ resource group คุณจะเป็น Owner ของทรัพยากรทั้งหมดในกลุ่มนั้น

ภาพด้านล่างแสดงสิทธิ์การเข้าถึงแบบ Owner ในระดับ subscription

การตรวจสอบ IAM สำหรับ resource group ภายใต้ subscription นั้นจะแสดงสิทธิ์การเข้าถึงแบบ Owner ที่สืบทอดมา

นั่นคือวิธีที่ระบบ RBAC ของ Azure ทำงานแบบลำดับชั้น ระบบจำนวนมากใช้โครงสร้างแบบลำดับชั้นที่คล้ายกัน ในบทเรียนนี้เราจะนำโมเดลที่เทียบเคียงกันได้มาใช้กับ Casbin

การทำงานของ Casbin​

ความเข้าใจเกี่ยวกับองค์ประกอบหลักของ Casbin (request, policy, matcher, effect) จะช่วยให้การออกแบบและปรับแต่งโมเดล RBAC ของคุณทำได้ง่ายขึ้น

ACL คืออะไร?​

ACL (Access Control List) ทำการแมปผู้ใช้ไปยังการกระทำ และการกระทำไปยังทรัพยากร

นิยามโมเดล​

โมเดล ACL แบบขั้นต่ำ:

[request_definition]
r = sub, act, obj

[policy_definition]
p = sub, act, obj

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = r.sub == p.sub && r.obj == p.obj && r.act == p.act
  1. request_definition — กำหนดรูปแบบของคำขอ เช่น alice, write, data1 หมายถึง “Alice สามารถเขียนข้อมูล data1 ได้หรือไม่?”
  2. policy_definition — กำหนดรูปแบบของนโยบาย เช่น นโยบาย alice, write, data1 ให้สิทธิ์ Alice ในการเขียนข้อมูล data1
  3. policy_effect — วิธีรวมผลจากนโยบายหลายรายการที่ตรงกัน (เช่น allow-override)
  4. matchers — เงื่อนไขที่ต้องเป็นจริง: r.sub == p.sub && r.obj == p.obj && r.act == p.act

ลองใช้งานใน Casbin editor​

เปิด Casbin editor แล้ววางโมเดลข้างต้นลงในช่อง Model editor

วางข้อความต่อไปนี้ในช่อง Policy editor:

p, alice, read, data1
p, bob, write, data2

และวางข้อความต่อไปนี้ในช่อง Request editor:

alice, read, data1

ผลลัพธ์จะเป็นดังนี้:

true

การแสดงภาพของโมเดล ACL, นโยบาย และการจับคู่คำขอ​

RBAC คืออะไร?​

RBAC (Role-Based Access Control) กำหนดให้ผู้ใช้มีบทบาท; บทบาทจะมีสิทธิ์ในการดำเนินการบนทรัพยากร คำขอจะตรวจสอบว่าบทบาทของผู้ใช้อนุญาตให้ดำเนินการกับทรัพยากรนั้นหรือไม่

นิยามโมเดล​

โมเดล RBAC แบบง่าย:

[request_definition]
r = sub, act, obj

[policy_definition]
p = sub, act, obj

[role_definition]
g = _, _
g2 = _, _

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = r.sub == p.sub && g(p.act, r.act) && r.obj == p.obj
  1. role_definition — กำหนดความสัมพันธ์แบบกราฟ (เช่น g สำหรับ role–role หรือ user–role) โดย matcher จะใช้สิ่งเหล่านี้เพื่อแก้ไขบทบาทและสิทธิ์

ลองใช้งานใน Casbin editor​

เปิด editor แล้ววางโมเดลข้างต้น

วางข้อความต่อไปนี้ในช่อง Policy editor:

p, alice, reader, data1
p, bob, owner, data2

g, reader, read
g, owner, read
g, owner, write

และวางข้อความต่อไปนี้ในช่อง Request editor:

alice, read, data1
alice, write, data1
bob, write, data2
bob, read, data2
bob, write, data1

ผลลัพธ์จะเป็นดังนี้:

true
false
true
true
false

การแสดงภาพของโมเดล RBAC, นโยบาย และการจับคู่คำขอ​

ความสัมพันธ์ g (role-to-action) เป็นกราฟ ซึ่งในนโยบายจะเขียนในรูปแบบของเส้นเชื่อม (edges) ตัวอย่างเช่น:

g, reader, read
g, owner, read
g, owner, write
ข้อมูล

p คือนโยบายปกติ (เปรียบเทียบด้วย ==) ส่วน g คือความสัมพันธ์แบบกราฟ คุณสามารถเพิ่มความสัมพันธ์อื่นได้โดยใช้ suffix เช่น g2, g3 ฯลฯ

RBAC แบบลำดับชั้น​

ในระบบ RBAC แบบลำดับชั้น จะมี resource types หลายประเภทที่มีการสืบทอด (เช่น Subscription → ResourceGroup) subscription sub1 สามารถมี resource groups rg1, rg2 อยู่ภายใน ในทำนองเดียวกัน จะมีบทบาท/การกระทำในระดับ subscription และในระดับ resource group พร้อมกับการสืบทอดระหว่างกัน ตัวอย่างเช่น บทบาทระดับ subscription sub-owner อาจสืบทอดไปยังบทบาทระดับ resource-group rg-owner: หากฉันมีสิทธิ์ sub-owner บน sub1 ฉันก็จะมีสิทธิ์ rg-owner บน rg1 และ rg2 โดยปริยาย

นิยามโมเดล​

โมเดล RBAC แบบลำดับชั้นขั้นต่ำ:

[request_definition]
r = sub, act, obj

[policy_definition]
p = sub, act, obj

[role_definition]
g = _, _
g2 = _, _

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = r.sub == p.sub && g(p.act, r.act) && g2(p.obj, r.obj)

โดยที่ g เชื่อมโยงบทบาท/การกระทำ และ g2 เชื่อมโยงทรัพยากร (เช่น จาก subscription ไปยัง resource group)

ลองใช้งานใน Casbin editor​

เปิด editor แล้ววางโมเดลด้านบนลงไป

วางข้อความต่อไปนี้ใน Policy editor:

p, alice, sub-reader, sub1
p, bob, rg-owner, rg2

// subscription role to subscription action mapping
g, sub-reader, sub-read
g, sub-owner, sub-read
g, sub-owner, sub-write

// resourceGroup role to resourceGroup action mapping
g, rg-reader, rg-read
g, rg-owner, rg-read
g, rg-owner, rg-write

// subscription role to resourceGroup role mapping
g, sub-reader, rg-reader
g, sub-owner, rg-owner

// subscription resource to resourceGroup resource mapping
g2, sub1, rg1
g2, sub2, rg2

และวางข้อความต่อไปนี้ใน Request editor:

alice, rg-read, rg1

ผลลัพธ์จะเป็นดังนี้:

true

ภาพแสดงการจับคู่ระหว่างโมเดล RBAC, นโยบาย และคำขอ​

เส้นเชื่อม g (role → action, role → role) สามารถเขียนในนโยบายได้ดังนี้:

// subscription role to subscription action mapping
g, sub-reader, sub-read
g, sub-owner, sub-read
g, sub-owner, sub-write

// resourceGroup role to resourceGroup action mapping
g, rg-reader, rg-read
g, rg-owner, rg-read
g, rg-owner, rg-write

// subscription role to resourceGroup role mapping
g, sub-reader, rg-reader
g, sub-owner, rg-owner

เส้นเชื่อม g2 จับคู่ subscription กับ resource group:

// subscription resource to resourceGroup resource mapping
g2, sub1, rg1
g2, sub2, rg2

ภาพแสดงการจับคู่ Subject​

ภาพแสดงการจับคู่ Action​

ภาพแสดงการจับคู่ Object​

ข้อมูล

Casbin จะประเมินคำขอเทียบกับนโยบายทั้งหมด หากมีนโยบายอย่างน้อยหนึ่งรายการที่ตรงกับคำขอ ผลลัพธ์จะเป็น true; มิฉะนั้นจะเป็น false.

สรุป​

บทเรียนนี้แสดงให้เห็นว่า ACL, RBAC และ hierarchical RBAC สามารถนำเสนอในรูปแบบของ Casbin ได้อย่างไร ในบทความตอนต่อไป เราจะนำไปใช้งานจริงในแอปพลิเคชัน Spring Boot และปกป้อง API ด้วย Casbin
