Casbin vs. Cedar

Cedar es un lenguaje de políticas de código abierto y un motor de evaluación creado en AWS; es el lenguaje detrás de Amazon Verified Permissions. Casbin es una biblioteca de autorización bajo la Fundación Apache Software con un modelo configurable e implementaciones en muchos lenguajes. Ambos evalúan solicitudes dentro de su aplicación; difieren en cómo se expresan las reglas y en lo que rodea al motor.

Resumen​

Lenguaje de políticas versus modelo configurable​

Una política de Cedar se lee como una frase:

permit (
    principal in Role::"editor",
    action == Action::"update",
    resource in Folder::"articles"
)
when { resource.owner == principal };

El lenguaje tiene un significado fijo: todo se deniega a menos que coincida un permit, y cualquier forbid coincidente gana. Las políticas pueden verificarse contra un esquema antes de ser desplegadas, y el diseño permite razonamiento automatizado sobre lo que un conjunto de políticas permite.

Casbin divide la misma regla en un modelo y datos. Aquí el objeto de solicitud es un artículo con campos Folder y Owner (ABAC):

[matchers]
m = g(r.sub, p.sub) && r.obj.Folder == p.obj && r.act == p.act && r.obj.Owner == r.sub
p, editor, articles, update
g, alice, editor

El modelo decide cómo se comparan las solicitudes y las reglas de política y cómo se combinan los resultados. Esa flexibilidad es el punto del diseño PERM de Casbin: el mismo motor puede comportarse como un simple ACL, como RBAC con tenants, como deny-override, o como una lista ordenada estilo firewall. Vea Cómo funciona y Modelos soportados.

Lo que rodea al motor​

Cedar le da un evaluador. Cargar entidades, almacenar políticas y distribuir cambios queda a cargo de su aplicación, o de Amazon Verified Permissions si usa AWS.

Casbin incluye esas piezas:

  • Los Adapters persisten la política en bases de datos SQL y NoSQL, archivos y almacenes en la nube.
  • Los Watchers mantienen sincronizadas múltiples instancias.
  • Los Role managers resuelven jerarquías de roles, incluyendo desde fuentes externas como LDAP o un proveedor de identidad.
  • La Management API y la RBAC API permiten a los administradores cambiar permisos en tiempo de ejecución.
  • Existe Middleware para la mayoría de los frameworks web.

Idiomas​

La implementación de referencia de Cedar está en Rust, con enlaces y puertos para algunos otros lenguajes.

Casbin ha mantenido implementaciones nativas para Go, Java, Node.js, Python, .NET, PHP, Rust, C++ y más, y un modelo y política escritos una vez funcionan en todos ellos.

Cuándo elegir cuál​

Elija Cedar si desea un lenguaje de políticas legible con validación de esquema y análisis formal, o planea usar Amazon Verified Permissions.

Elija Casbin si necesita elegir o personalizar el modelo de control de acceso, desea que las APIs de almacenamiento, sincronización y gestión estén incluidas, necesita una biblioteca nativa en su lenguaje, o prefiere un proyecto bajo la gobernanza de Apache Software Foundation que no dependa de un único proveedor de nube.

Pruebe Casbin​

Pruebe un modelo y política en el editor en línea, o siga el tutorial para Go, Node.js, Python o Java.

Términos de Servicio

Apache Casbin (Incubating) es un esfuerzo en proceso de incubación en The Apache Software Foundation (ASF), patrocinado por Apache Incubator. La incubación es obligatoria para todos los proyectos recién aceptados hasta que una revisión adicional indique que la infraestructura, las comunicaciones y el proceso de toma de decisiones se han estabilizado de manera consistente con otros proyectos exitosos de ASF. Si bien el estado de incubación no refleja necesariamente la completitud o estabilidad del código, indica que el proyecto aún no ha sido plenamente respaldado por ASF.
