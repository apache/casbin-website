Tutorial RBAC Spring Boot: Control de acceso basado en roles con jCasbin

Este tutorial añade control de acceso basado en roles (RBAC) a una API REST construida con Spring Boot y jCasbin. Al final, tres roles (admin, editor, viewer) tienen permitido diferentes métodos HTTP en diferentes rutas, y las reglas residen en un archivo de política que puede cambiar sin tocar los controladores.

El mismo modelo y política funcionan en cada implementación de Casbin, por lo que puede reutilizarlos en las versiones Go, Node.js, Python y Rust de este tutorial.

1. Añadir la dependencia​

En un proyecto Spring Boot 3 que ya tiene spring-boot-starter-web, añada jCasbin a pom.xml. Use la última versión de Maven Central.

<dependency>
    <groupId>org.casbin</groupId>
    <artifactId>jcasbin</artifactId>
    <version>1.81.0</version>
</dependency>

2. Escribir el modelo​

El modelo indica cómo es una solicitud y cómo se compara con la política. Guarde esto como model.conf en el directorio desde el cual inicia la aplicación:

[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[role_definition]
g = _, _

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = g(r.sub, p.sub) && keyMatch2(r.obj, p.obj) && regexMatch(r.act, p.act)
  • r = sub, obj, act: cada solicitud es un usuario, una ruta URL y un método HTTP.
  • g = _, _: los usuarios pueden asignarse a roles.
  • g(r.sub, p.sub): el usuario de la solicitud debe tener el rol nombrado en la regla de política.
  • keyMatch2 coincide con rutas como /api/articles/:id, y regexMatch permite que una regla liste varios métodos. Vea Funciones para los otros comparadores integrados.

3. Escribir la política​

Guarde esto como policy.csv junto a model.conf:

p, admin, /api/*, (GET)|(POST)|(PUT)|(DELETE)
p, editor, /api/articles, (GET)|(POST)
p, editor, /api/articles/:id, (GET)|(PUT)
p, viewer, /api/articles, GET
p, viewer, /api/articles/:id, GET

g, alice, admin
g, bob, editor
g, carol, viewer

Las líneas que empiezan con p otorgan a un rol acceso a una ruta y un conjunto de métodos. Las líneas que empiezan con g asignan usuarios a roles.

4. Añadir el interceptor​

El interceptor llama a enforce con el usuario, la ruta y el método, y responde con 403 Forbidden cuando Casbin dice que no.

AuthorizationInterceptor.java
package com.example.rbac;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.casbin.jcasbin.main.Enforcer;
import org.springframework.web.servlet.HandlerInterceptor;

public class AuthorizationInterceptor implements HandlerInterceptor {

    private final Enforcer enforcer;

    public AuthorizationInterceptor(Enforcer enforcer) {
        this.enforcer = enforcer;
    }

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        // Replace this with the user from your session or JWT.
        String user = request.getHeader("X-User");
        if (user == null) {
            user = "";
        }

        if (enforcer.enforce(user, request.getRequestURI(), request.getMethod())) {
            return true;
        }
        response.sendError(HttpServletResponse.SC_FORBIDDEN, "forbidden");
        return false;
    }
}

Cree el Enforcer como un bean y registre el interceptor para las rutas de la API:

CasbinConfig.java
package com.example.rbac;

import org.casbin.jcasbin.main.Enforcer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class CasbinConfig implements WebMvcConfigurer {

    @Bean
    public Enforcer enforcer() {
        return new Enforcer("model.conf", "policy.csv");
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new AuthorizationInterceptor(enforcer())).addPathPatterns("/api/**");
    }
}

Un controlador a proteger:

ArticleController.java
package com.example.rbac;

import java.util.List;
import java.util.Map;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/articles")
public class ArticleController {

    @GetMapping
    public Map<String, Object> list() {
        return Map.of("articles", List.of());
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Map<String, Object> create() {
        return Map.of("created", true);
    }

    @PutMapping("/{id}")
    public Map<String, Object> update(@PathVariable long id) {
        return Map.of("updated", id);
    }

    @DeleteMapping("/{id}")
    public Map<String, Object> delete(@PathVariable long id) {
        return Map.of("deleted", id);
    }
}
nota

new Enforcer("model.conf", "policy.csv") lee los dos archivos desde el directorio de trabajo. Los archivos empaquetados dentro del JAR de la aplicación bajo src/main/resources no se pueden abrir como rutas de archivo; mantenga los archivos fuera del JAR, o cargue la política desde una base de datos con un adaptador.

La cabecera X-User mantiene el ejemplo breve. Casbin solo gestiona la autorización; en una aplicación real, el nombre de usuario proviene de su capa de autenticación, como Spring Security, un JWT verificado o una sesión.

5. Pruébalo​

mvn spring-boot:run
curl -i -X POST   -H "X-User: bob"   http://localhost:8080/api/articles     # 201, editors can create
curl -i -X DELETE -H "X-User: bob"   http://localhost:8080/api/articles/1   # 403, editors cannot delete
curl -i -X DELETE -H "X-User: alice" http://localhost:8080/api/articles/1   # 200, admins can
curl -i -X POST   -H "X-User: carol" http://localhost:8080/api/articles     # 403, viewers are read-only

6. Cambiar roles en tiempo de ejecución​

Los roles y permisos son datos, por lo que puede cambiarlos mientras el servidor está en ejecución. Inyecte el bean Enforcer donde gestione usuarios:

enforcer.addRoleForUser("dave", "editor");            // dave becomes an editor
enforcer.deleteRoleForUser("bob", "editor");          // bob is no longer an editor
enforcer.addPolicy("editor", "/api/comments", "POST"); // editors may now post comments

List<String> roles = enforcer.getRolesForUser("alice"); // [admin]

La lista completa está en la API RBAC y la API de gestión.

Próximos pasos​

  • Almacene la política en una base de datos. Reemplace policy.csv con un adaptador para JDBC, MyBatis, Hibernate, MongoDB y otros. Los cambios de política realizados a través de la API se guardan automáticamente.
  • Utilice el starter de Spring Boot. casbin-spring-boot-starter crea el Enforcer y un adaptador JDBC desde application.yml.
  • Ejecute más de una instancia. Utilice un watcher para que cada instancia recargue la política cuando una de ellas la cambie.
  • Aplicaciones multi-tenant. RBAC con dominios otorga a un usuario diferentes roles en diferentes tenants.
  • Reglas basadas en atributos. Combine roles con ABAC, por ejemplo, "los editores solo pueden actualizar sus propios artículos". Elección de un modelo de control de acceso muestra un modelo combinado.
  • Otros frameworks. La lista de middleware tiene plugins para Spring Boot, Apache Shiro, JFinal, Nutz y otros frameworks.

Apache Casbin (Incubating) es un esfuerzo en proceso de incubación en The Apache Software Foundation (ASF), patrocinado por Apache Incubator. La incubación es obligatoria para todos los proyectos recién aceptados hasta que una revisión adicional indique que la infraestructura, las comunicaciones y el proceso de toma de decisiones se han estabilizado de manera consistente con otros proyectos exitosos de ASF. Si bien el estado de incubación no refleja necesariamente la completitud o estabilidad del código, indica que el proyecto aún no ha sido plenamente respaldado por ASF.
