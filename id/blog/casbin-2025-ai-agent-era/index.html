Casbin di Tahun 2025: Otorisasi untuk Era Agen AI

11 Desember 2025 · Dibaca dalam 1 menit
Yang Luo
Creator of Casbin

Tahun 2024 adalah tahun ketika agen AI beralih dari demo ke produksi. Model Context Protocol (MCP) telah diadopsi oleh Google, OpenAI, Microsoft, dan banyak lainnya, serta cara aplikasi berkomunikasi dengan layanan eksternal sedang berubah. Pergeseran tersebut membawa serangkaian tantangan otorisasi baru yang telah kami kerjakan di Casbin.

Dunia Telah Berubah​

Ketika kami memulai Casbin pada tahun 2017, skenario otorisasi tipikal cukup lugas: seorang pengguna membuat permintaan, kami memeriksa apakah mereka memiliki izin, selesai. Sekarang? Sebuah agen AI mungkin bertindak atas nama pengguna, memanggil beberapa server MCP, masing-masing dengan izin tool mereka sendiri, dan seluruh proses harus terjadi dalam hitungan milidetik di edge.

Spesifikasi MCP sekarang mengklasifikasikan server MCP sebagai OAuth 2.0 Resource Servers (pembaruan Juni 2025), dengan scopes terperinci seperti mcp:tools:weather atau mcp:resources:customer-data:read. Itulah jenis model izin granular yang dirancang untuk Casbin; integrasi dengan MCP dan OAuth masih memerlukan lebih banyak pekerjaan.

Yang Sedang Kami Kerjakan​

Otorisasi Server MCP​

Ini adalah salah satu fokus utama kami. Ketika agen AI memanggil server MCP, server harus memutuskan: bolehkah agen ini, atas nama pengguna ini, memanggil tool ini dengan parameter ini?

RBAC tradisional tidak cukup. Anda membutuhkan sesuatu seperti ABAC—misalnya “apakah agen ini diizinkan mengakses data pelanggan untuk wilayah Alice selama jam kerja?” Kami sedang mengeksplorasi bagaimana model policy Casbin dapat mengekspresikan batasan-batasan ini.

Kendalanya: server MCP harus memutuskan dengan sangat cepat. Kami sedang mempertimbangkan evaluasi policy ringan di dalam proses server MCP alih-alih memanggil layanan otorisasi terpisah.

Otorisasi Edge-First​

Cloudflare Workers, Deno Deploy, Vercel Edge Functions - ruang komputasi edge telah meledak. Pada tahun 2025, waktu respons di bawah 50ms adalah standar dasar, dan Anda tidak mampu menambahkan 100ms untuk pemeriksaan otorisasi ke server pusat tertentu.

Hal ini mendorong kami untuk berpikir berbeda tentang cara kerja Casbin. Bisakah kami mengompilasi policy ke WebAssembly dan menjalankannya secara langsung di V8 isolates? Bisakah kami melakukan caching policy cerdas di edge sambil mempertahankan konsistensi? Ini adalah masalah sulit, dan kami belum memiliki semua jawabannya, tetapi inilah arah yang dituju.

Kami sangat tertarik pada ekosistem Cloudflare Workers - mereka telah membangun platform lengkap untuk server MCP dengan dukungan OAuth bawaan. Integrasi Casbin native di sana bisa sangat kuat.

Otorisasi Pipeline RAG​

Tema yang berulang: perusahaan yang membangun sistem RAG di mana LLM harus mengakses dokumen internal, tetapi setiap pengguna hanya boleh melihat dokumen yang diizinkan untuk mereka lihat.

OWASP Top 10 untuk Aplikasi LLM 2025 mencantumkan “Sensitive Information Disclosure” sebagai risiko utama. Solusinya bukan hanya memfilter output, tetapi memastikan LLM tidak pernah mengambil dokumen yang tidak diotorisasi untuk diakses oleh pengguna.

Jadi otorisasi harus terjadi di level kueri vector store. Kami sedang mempertimbangkan mengubah policy Casbin menjadi filter metadata untuk DB vektor—yaitu pemeriksaan izin menjadi klausa WHERE yang didorong ke bawah ke retrieval.

Skenario Multi-Agen​

Dengan beberapa agen dalam rantai (misalnya agen coding → agen deployment → agen monitoring), delegasi izin itu rumit. Setiap agen mungkin memiliki kemampuan berbeda, dan Anda harus melacak rantai penuh.

Alur On-Behalf-Of (OBO) OAuth mencakup sebagian dari ini, tetapi logika untuk “bolehkah agen B melakukan X atas nama agen A atas nama pengguna alice” membutuhkan model yang jelas. Hierarki peran Casbin dan domain RBAC dapat diperluas ke hierarki agen; kami sedang mengerjakan semantiknya.

Hal-Hal Tradisional dalam Roadmap​

Tentu saja, kami tidak meninggalkan hal-hal dasar. Beberapa hal praktis dalam daftar kami:

Implementasi bahasa yang mengejar ketertinggalan - SwiftCasbin dan Lua-Casbin masih tertinggal dalam fitur dibandingkan versi Go dan Node.js. Operator in, WatcherEx, caching yang lebih baik untuk fungsi g - ini perlu konsisten di mana-mana.

Middleware framework baru - go-zero telah diminta berulang kali. Poem untuk Rust semakin populer. Play Framework untuk Java sudah ada di wishlist sejak lama.

Pekerjaan performa - Seiring policy menjadi lebih kompleks untuk use case baru ini, kecepatan evaluasi menjadi lebih penting. Kami membutuhkan benchmarking, profiling, dan optimasi yang lebih baik di semua implementasi.

Yang Belum Kami Ketahui​

Ruang otorisasi agen AI bergerak sangat cepat; kami belajar sambil berjalan. Pertanyaan yang masih terbuka:

  • Apakah Casbin harus memiliki primitif kelas satu untuk "identitas agen" vs "identitas pengguna"?
  • Bagaimana Anda menangani otorisasi untuk alat yang ditemukan secara dinamis melalui MCP?
  • Apa strategi caching yang tepat ketika kebijakan mungkin bergantung pada konteks waktu nyata?

Jika Anda membangun di ruang ini dan mengalami masalah otorisasi, kami ingin mendengar dari Anda. Fitur terbaik berasal dari kasus penggunaan nyata.

Getting involved​

Kami telah menjadi organisasi GSoC selama bertahun-tahun, dan topik terkait AI ini cocok untuk proyek musim panas. Anda tidak perlu menunggu GSoC—jika ini terdengar menarik, hubungi kami di Discord atau buka issue di GitHub.

Beberapa tahun ke depan akan sangat dinamis bagi otorisasi. Masalahnya lebih sulit, tetapi juga lebih menarik. Kami bersemangat untuk mencari solusinya bersama.

Apache Casbin (Incubating) adalah upaya yang sedang mengalami inkubasi di The Apache Software Foundation (ASF), disponsori oleh Apache Incubator. Inkubasi diperlukan untuk semua proyek yang baru diterima sampai tinjauan lebih lanjut menunjukkan bahwa infrastruktur, komunikasi, dan proses pengambilan keputusan telah stabil dengan cara yang konsisten dengan proyek ASF lainnya yang berhasil. Meskipun status inkubasi tidak selalu mencerminkan kelengkapan atau stabilitas kode, hal itu menunjukkan bahwa proyek tersebut belum sepenuhnya didukung oleh ASF.
