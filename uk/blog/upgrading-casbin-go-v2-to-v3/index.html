Оновлення Casbin (Go) з v2 до v3: Повний посібник з міграції

1 лютого 2026 р. · Читання за 8 хв
Yang Luo
Creator of Casbin

Якщо ви використовуєте Casbin v2 у продакшені та замислюєтеся над шляхом оновлення до v3, цей посібник саме для вас. Ми розглянемо все, що вам потрібно знати про перехід: від розуміння того, що змінилося, до безпечної міграції у продакшені.

Що змінилося у v3?​

Гарна новина: v3 — це переважно зміна шляху модуля зі зворотною сумісністю. Основна логіка авторизації, API та функціональність залишаються незмінними. Це було свідоме рішення, щоб мінімізувати порушення роботи системи, дотримуючись при цьому конвенцій семантичного версіонування Go.

Основна зміна: Шлях модуля​

Єдина несумісна зміна у v3 — це шлях модуля Go:

// v2
import "github.com/casbin/casbin/v2"

// v3
import "github.com/casbin/casbin/v3"

І все. Вашим наявним політикам, моделям та логіці коду не потрібно змінюватися. Міграція є механічною: оновіть оператори import та файл go.mod.

Чому випуск v3?​

Ви можете запитати, навіщо випускати нову мажорну версію лише для зміни шляху import. Відповідь — семантичне версіонування. Система модулів Go використовує номер мажорної версії у шляху import (/v2, /v3 тощо). Це дозволяє кільком мажорним версіям співіснувати в одному дереві залежностей, що критично важливо для великих додатків із багатьма залежностями.

Випустивши v3, ми:

  • Привели відповідність до семантичного версіонування import у Go
  • Увімкнули поступову міграцію в складних графах залежностей
  • Підготували ґрунт для майбутніх покращень без порушення роботи існуючих користувачів v2

Що залишилося незмінним?​

Все інше. Серйозно.

  • Усі API залишаються ідентичними - Enforce(), AddPolicy(), GetAllRoles() та будь-який інший метод працюють точно так само, як і раніше
  • Синтаксис моделей та політик незмінний - Ваші існуючі файли моделей .conf та файли політик .csv працюють без модифікацій
  • Інтерфейс адаптера незмінний - Методи persist.Adapter залишаються тими самими; адаптерам потрібна лише збірка проти шляху модуля v3
  • Характеристики продуктивності - Немає регресій чи покращень продуктивності; це той самий рушій
  • Інтеграції проміжного ПЗ (middleware) - Middleware працює так само, щойно він імпортує ту саму мажорну версію, що і ваш enforcer

Нові можливості у v3​

Після випуску v3.0.0 у грудні 2025 року було додано кілька нових можливостей:

v3.7.0+: Покращена інтеграція логування​

Тепер ви можете інтегрувати власні логери в операції базового виконання політик та управління ними в Casbin, забезпечуючи кращу спостережуваність:

enforcer.SetLogger(yourCustomLogger)

v3.8.0+: API GetAllUsers()​

Новий API для розрізнення користувачів та ролей:

users, err := enforcer.GetAllUsers()

Це особливо корисно в системах RBAC, де потрібно окремо виводити список фактичних користувачів та визначень ролей.

v3.9.0+: Вбудоване виявлення циклів​

Enforcer тепер включає автоматичне виявлення циклів у ієрархіях ролей, запобігаючи нескінченним циклам:

// Automatically detects and prevents circular role assignments
enforcer.AddGroupingPolicy("alice", "admin")
enforcer.AddGroupingPolicy("admin", "alice") // Will be detected as a cycle

v3.10.0+: API Explain() для аналізу авторизації за допомогою AI​

Найновіша можливість використовує LLM API для пояснення рішень щодо авторизації природною мовою:

enforcer.SetAIConfig(casbin.AIConfig{
    Endpoint: "https://api.openai.com/v1/chat/completions",
    APIKey:   os.Getenv("OPENAI_API_KEY"),
    Model:    "gpt-4",
})

explanation, err := enforcer.Explain("alice", "data1", "read")
// e.g. "Alice can read data1 because she has the 'reader' role..."

Це особливо цінно для налагодження складних політик та допомоги нетехнічним зацікавленим сторонам у розумінні рішень щодо авторизації.

Migration Strategy​

For New Projects​

Просто: використовуйте v3 з самого початку.

go get github.com/casbin/casbin/v3
import "github.com/casbin/casbin/v3"

For Existing v2 Projects​

Міграція складається з трьох кроків:

Step 1: Update Your go.mod​

go get github.com/casbin/casbin/v3
go mod tidy

Step 2: Update Import Statements​

Знайдіть і замініть усі імпорти Casbin у вашій кодовій базі:

# Using sed on Unix/Linux/Mac
find . -type f -name '*.go' -exec sed -i 's|github.com/casbin/casbin/v2|github.com/casbin/casbin/v3|g' {} +

# Or manually in your editor
# Find: github.com/casbin/casbin/v2
# Replace: github.com/casbin/casbin/v3

Step 3: Update Adapter Imports (If Applicable)​

Адаптер реалізує persist.Adapter для однієї конкретної основної версії, оскільки model.Model у casbin/v2 та casbin/v3 є різними типами Go. Тому enforcer v3 потребує випуску адаптера, який імпортує github.com/casbin/casbin/v3. Перевірте go.mod адаптера:

// Example: the PostgreSQL adapter already depends on casbin/v3
import pgadapter "github.com/apache/casbin-pg-adapter"

// The file adapter is built in and ships with each major version

Якщо ваш адаптер ще не оновлено, залиштеся на v2 для цього сервісу до його оновлення або створіть issue в репозиторії адаптера.

Rollback Plan​

Якщо вам потрібно відкотити зміни:

  1. Code level: Відкатіть зміни імпортів (використовуйте систему контролю версій)
  2. Dependency level: go get github.com/casbin/casbin/v2@latest
  3. Deploy: Використовуйте стандартний процес розгортання для відкату

Краса цієї міграції полягає в тому, що відкат є тривіальним — просто поверніть зміни імпортів і повторно розгорніть додаток.

Do I Need to Migrate My Policy Database?​

No. Ваші наявні дані політик залишаються незмінними. Політики зберігаються як прості рядки (subject, object, action тощо) і не залежать від версії Casbin.

Testing Your Migration​

Automated Testing​

Ваші наявні тести повинні проходити без модифікацій:

func TestPolicyEnforcement(t *testing.T) {
    // This test works identically in v2 and v3
    e, _ := casbin.NewEnforcer("model.conf", "policy.csv")
    
    ok, _ := e.Enforce("alice", "data1", "read")
    if !ok {
        t.Error("Expected alice to have read access to data1")
    }
}

Integration Testing​

Middleware, який приймає *casbin.Enforcer, прив'язаний до однієї основної версії так само, як і адаптери. Якщо ваш middleware все ще імпортує casbin/v2, прямий виклик enforcer вимагає лише кількох рядків коду:

// Example with Gin
import (
    "net/http"

    "github.com/casbin/casbin/v3"
    "github.com/gin-gonic/gin"
)

func Authorizer(e *casbin.Enforcer) gin.HandlerFunc {
    return func(c *gin.Context) {
        ok, err := e.Enforce(c.GetString("user"), c.Request.URL.Path, c.Request.Method)
        if err != nil || !ok {
            c.AbortWithStatus(http.StatusForbidden)
            return
        }
        c.Next()
    }
}

Load Testing​

Запустіть стандартні тестування під навантаженням проти збірки v3. Характеристики продуктивності мають бути ідентичними до v2.

Policy Verification​

Порівняйте оцінку політик між версіями:

# Export policies from v2
# Load into v3
# Run test cases against both
# Compare results

Якщо ви помітите будь-які відмінності, це, ймовірно, баг — будь ласка, повідомте про нього!

Common Pitfalls​

Pitfall 1: Mixed v2/v3 Dependencies​

Problem: Деякі залежності використовують Casbin v2, інші — v3, що спричиняє конфлікти.

Solution: Сама збірка працює нормально: система модулів Go розглядає v2 і v3 як окремі пакети, тому обидва можуть перебувати в одному дереві залежностей. Чого ви не можете робити — передавати enforcer v3 бібліотеці, яка очікує enforcer v2. Тримайте enforcer, його адаптер і middleware на одній основній версії.

Pitfall 2: Adapter Version Mismatch​

Problem: Використання адаптера v2 з Casbin v3 (або навпаки).

Solution: Це проявляється як помилка компіляції, а не сюрприз під час виконання. Перевірте, яку основну версію Casbin вимагає go.mod адаптера, і використовуйте реліз, який відповідає вашому enforcer.

Pitfall 3: Forgetting Internal Packages​

Problem: Оновлені імпортні оператори основного додатка, але забуто внутрішні пакети або інструменти.

Solution: Використовуйте go mod graph та go mod why, щоб знайти всі залежності Casbin:

go mod graph | grep casbin

Pitfall 4: Custom Adapter Compilation Issues​

Проблема: Власний адаптер не компілюється після оновлення.

Рішення: Інтерфейс адаптера не змінився, тому це вказує на проблему з імпортом. Перевірте, що всі іморти Casbin у вашому адаптері використовують v3:

import (
    "github.com/casbin/casbin/v3"
    "github.com/casbin/casbin/v3/persist"
)

FAQ​

Q: Чи підтримується ще v2?​

На момент написання цього тексту, v2 отримує критичні виправлення помилок, але нові функції розробляються для v3. Плануйте міграцію протягом наступних 6-12 місяців.

Q: Чи можу я поступово мігрувати, залишивши одні сервіси на v2, а інші на v3?​

Так! Вони навіть можуть спільно використовувати одну базу політик. Це одна з переваг мінімальних змін у v3.

Q: Чи працюватиме мій проміжний код (middleware) (Gin, Echo, Fiber тощо)?​

Лише якщо він імпортує ту ж саму major версію, що й ваш ефорсер (enforcer). Перевірте go.mod middleware; якщо він досі на v2, викликайте Enforce() з власного невеликого обробника, як показано вище.

Q: Чи потрібно мені оновлювати мої .conf файли моделей?​

Ні. Синтаксис файлів моделей не змінився.

Q: Чи потрібно мені оновлювати мої .csv файли політик?​

Ні. Формат файлів політик не змінився.

Q: А як щодо WatcherEx, FilteredAdapter та інших інтерфейсів?​

Усі інтерфейси залишаються незмінними. Якщо ваш код реалізує ці інтерфейси, модифікації не потрібні (окрім шляхів імпорту).

Q: Вплив на продуктивність?​

Відсутній. v3 використовує той самий рушій оцінювання, що й v2.

Q: Чи можу я використовувати v3 з Go 1.16?​

Перевірте go.mod у репозиторії Casbin v3 для визначення мінімально підтримуваної версії Go. Загалом рекомендується використовувати останню стабільну версію Go.

Умови використання

Apache Casbin (Incubating) — це проєкт, який проходить інкубацію в Apache Software Foundation (ASF) під егідою Apache Incubator. Інкубація є обов'язковою для всіх щойно прийнятих проєктів, доки подальший огляд не покаже, що інфраструктура, комунікації та процеси прийняття рішень стабілізувалися відповідно до інших успішних проєктів ASF. Хоча статус інкубації не обов'язково відображає повноту або стабільність коду, він свідчить про те, що проєкт ще не отримав повного схвалення з боку ASF.
