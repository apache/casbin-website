Commencer

Nouveau sur Casbin ? Lisez ce qu'est Casbin, puis choisissez un modèle : RBAC, ABAC, ReBAC, ou comparez tous les modèles de contrôle d'accès.

Installation​

go get github.com/casbin/casbin/v3
Migration de v2 vers v3

Si vous effectuez une mise à niveau depuis Casbin v2 vers v3, mettez à jour vos chemins d'importation de github.com/casbin/casbin/v2 à github.com/casbin/casbin/v3. Cela s'applique également à tous les sous-packages (par exemple, v2/model devient v3/model).

Pour les modules Go, exécutez :

go get -u github.com/casbin/casbin/v3

Puis mettez à jour toutes les importations dans votre code de /v2 à /v3.

Pour Maven :

<!-- https://mvnrepository.com/artifact/org.casbin/jcasbin -->
<dependency>
    <groupId>org.casbin</groupId>
    <artifactId>jcasbin</artifactId>
    <version>1.x.y</version>
</dependency>

Prise en charge de GraalVM Native Image​

Si vous construisez une application native avec GraalVM (par exemple, en utilisant Quarkus ou Spring Native), jCasbin nécessite une configuration spéciale en raison de son utilisation du moteur d'expressions Aviator.

Par défaut, Aviator utilise la génération dynamique de classes via ASM, ce qui n'est pas pris en charge dans les images natives GraalVM. Pour résoudre ce problème, vous devez configurer Aviator pour utiliser le mode interpréteur au lieu du mode compilation.

Pour les applications Quarkus​

Ajoutez ce qui suit à votre application.properties ou pom.xml :

<properties>
    <quarkus.native.additional-build-args>
        -J-Daviator.eval.mode=INTERPRETER
    </quarkus.native.additional-build-args>
</properties>

Pour les autres builds natifs GraalVM​

Définissez la propriété système lors de la construction de l'image native :

-Daviator.eval.mode=INTERPRETER

Ou configurez-le par programmation avant d'initialiser jCasbin :

System.setProperty("aviator.eval.mode", "INTERPRETER");
note

Cette configuration permet de passer Aviator de son mode de compilation par défaut à son mode interpréteur. Bien que cela puisse avoir un léger impact sur les performances, cela permet une compatibilité totale avec les images natives GraalVM en évitant la génération de classes à l'exécution.

# NPM
npm install casbin --save

# Yarn
yarn add casbin

Exigez ce package dans le composer.json de votre projet pour télécharger le package :

composer require casbin/casbin

Si vous recevez l'erreur "Your user does not have write permissions in /usr/local/lib/luarocks/rocks", exécutez la commande avec des privilèges élevés ou installez-la dans votre arborescence locale en utilisant le flag --local :

luarocks install casbin --local

Créer un Enforcer Casbin​

Casbin repose sur des fichiers de configuration pour spécifier le modèle de contrôle d'accès.

Vous avez besoin de deux fichiers de configuration : model.conf et policy.csv. Le fichier model définit votre modèle de contrôle d'accès ; le fichier policy contient les règles de permission. En pratique, vous travaillez avec un seul composant—l'Enforcer—qui charge les deux fichiers lors de sa création.

Pour créer un Enforcer, fournissez un Model et un Adapter.

Casbin fournit un FileAdapter que vous pouvez utiliser. Voir Adapter pour plus d'informations.

  • Exemple utilisant un fichier Model avec le FileAdapter par défaut :

import (
    "log"

    "github.com/casbin/casbin/v3"
    "github.com/casbin/casbin/v3/model"

// Initialize a Xorm adapter with MySQL database.

if err != nil {
    log.Fatalf("error: adapter: %s", err)
}

m, err := model.NewModelFromString(`
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = r.sub == p.sub && r.obj == p.obj && r.act == p.act
`)
if err != nil {
    log.Fatalf("error: model: %s", err)
}

e, err := casbin.NewEnforcer(m, a)
if err != nil {
    log.Fatalf("error: enforcer: %s", err)
}

import casbin_sqlalchemy_adapter


# Use SQLAlchemy Casbin adapter with SQLLite DB
adapter = casbin_sqlalchemy_adapter.Adapter('sqlite:///test.db')

# Create a config model policy
with open("rbac_example_model.conf", "w") as f:
    f.write("""
    [request_definition]
    r = sub, obj, act

    [policy_definition]
    p = sub, obj, act

    [policy_effect]
    e = some(where (p.eft == allow))

    [matchers]
    m = r.sub == p.sub && r.obj == p.obj && r.act == p.act
    """)

# Create enforcer from adapter and config policy
e = casbin.Enforcer('rbac_example_model.conf', adapter)

Vérifier les Permissions​

Ajoutez une vérification d'application dans votre code juste avant que la ressource ne soit accédée :

sub := "alice" // the user that wants to access a resource.
obj := "data1" // the resource that is going to be accessed.
act := "read" // the operation that the user performs on the resource.

ok, err := e.Enforce(sub, obj, act)

if err != nil {
    // handle err
}

if ok == true {
    // permit alice to read data1
} else {
    // deny the request, show an error
}

// You could use BatchEnforce() to enforce some requests in batches.
// This method returns a bool slice, and this slice's index corresponds to the row index of the two-dimensional array.
// e.g. results[0] is the result of {"alice", "data1", "read"}
results, err := e.BatchEnforce([][]interface{}{{"alice", "data1", "read"}, {"bob", "data2", "write"}, {"jack", "data3", "read"}})
String sub = "alice"; // the user that wants to access a resource.
String obj = "data1"; // the resource that is going to be accessed.
String act = "read"; // the operation that the user performs on the resource.

if (e.enforce(sub, obj, act) == true) {
    // permit alice to read data1
} else {
    // deny the request, show an error
}

Casbin fournit des API pour la gestion des permissions à l'exécution. Par exemple, vous pouvez récupérer tous les rôles attribués à un utilisateur :

roles, err := e.GetRolesForUser("alice")
List<String> roles = e.getRolesForUser("alice");
const roles = await e.getRolesForUser('alice');
$roles = $e->getRolesForUser("alice");
roles = e.get_roles_for_user("alice")
var roles = e.GetRolesForUser("alice");
roles = e.rolesForEntity("alice")
let roles = e.get_roles_for_user("alice");
local roles = e:GetRolesForUser("alice")

Pour plus d'exemples, voir Management API et RBAC API. Vous pouvez également parcourir les cas de test dans chaque dépôt de langage.
