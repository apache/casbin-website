Frontend Integration

Casbin.js bringt Casbin-artige Zugriffssteuerung ins Frontend: Definieren Sie Berechtigungen (z. B. von Ihrem Backend) und nutzen Sie diese, um UI-Elemente anzuzeigen/auszublenden oder Benutzer zu routen. Es funktioniert im manual-Modus (Sie setzen Berechtigungen im Code) oder im auto-Modus (Abruf von einer API).

Installation​

npm install casbin.js
npm install casbin

oder

yarn add casbin.js

Schnellstart​

Konfigurieren Sie Casbin.js im Modus manual, um Berechtigungen explizit in Ihrer Frontend-Anwendung festzulegen:

const casbinjs = require("casbin.js");
// Set the user's permission:
// He/She can read `data1` and `data2` objects and can write `data1` object
const permission = {
    "read": ["data1", "data2"],
    "write": ["data1"]
}

// Run casbin.js in manual mode, which requires you to set the permission manually.
const authorizer = new casbinjs.Authorizer("manual");

Mit einer Authorizer-Instanz können Sie Berechtigungen über authorizer.can() und authorizer.cannot() prüfen. Beide Methoden geben JavaScript-Promises zurück (siehe MDN-Dokumentation), verwenden Sie also die Methode then(), um die Ergebnisse zu verarbeiten:

result = authorizer.can("write", "data1");
result.then((success, failed) => {
    if (success) {
        console.log("you can write data1");
    } else {
        console.log("you cannot write data1");
    }
});
// output: you can write data1

Die Methode cannot() funktioniert identisch:

result = authorizer.cannot("read", "data2");
result.then((success, failed) => {
    if (success) {
        console.log("you cannot read data2");
    } else {
        console.log("you can read data2");
    }
});
// output: you can read data2

Der Parameter success zeigt an, dass die Abfrage ohne Fehler abgeschlossen wurde – nicht, dass eine Berechtigung erteilt wurde. Ebenso bezieht sich failed auf Abfragefehler, nicht auf die Verweigerung einer Berechtigung.

Siehe unser React-Beispiel für die praktische Verwendung von Casbin.js.

Berechtigungsobjekt​

Casbin.js verwendet ein JSON-Objekt zur Darstellung der Besucher-Berechtigungen. Beispiel:

{
    "read": ["data1", "data2"],
    "write": ["data1"]
}

Dieses Objekt zeigt an, dass der Besucher sowohl die Objekte data1 als auch data2 lesen kann, aber nur in data1 schreiben darf.

Erweiterte Verwendung​

Casbin.js bietet eine nahtlose Integration zwischen der Zugriffssteuerung im Frontend und Ihrem Backend-Casbin-Dienst.

Verwenden Sie den Modus auto und geben Sie beim Initialisieren des Casbin.js Authorizer Ihren Backend-Endpunkt an. Er synchronisiert automatisch Berechtigungen und verwaltet den Autorisierungszustand im Frontend:

const casbinjs = require('casbin.js');

// Set your backend Casbin service URL
const authorizer = new casbinjs.Authorizer(
    'auto', // mode
    {endpoint: 'http://your_endpoint/api/casbin'}
);

// Set your visitor.
// Casbin.js will automatically sync the permission with your backend Casbin service.
authorizer.setUser("Tom");

// Evaluate the permission
result = authorizer.can("read", "data1");
result.then((success, failed) => {
    if (success) {
        // Some frontend procedure ...
    }
});

Stellen Sie auf der Backend-Seite einen Endpunkt (wie z. B. eine REST-API) bereit, der das Berechtigungsobjekt für das Frontend generiert. Rufen Sie in Ihrem API-Controller CasbinJsGetUserPermission auf, um das Berechtigungsobjekt zu erstellen. Dieses Beego-Beispiel demonstriert das Muster:

Notiz

Ihr Endpunkt sollte eine Antwort wie diese zurückgeben:

{
    "other":"other",
    "data": "What you get from `CasbinJsGetPermissionForUser`"
}
// Router
beego.Router("api/casbin", &controllers.APIController{}, "GET:GetFrontendPermission")

// Controller
func (c *APIController) GetFrontendPermission() {
    // Get the visitor from the GET parameters. (The key is "casbin_subject")
    visitor := c.Input().Get("casbin_subject")
    // `e` is an initialized instance of Casbin Enforcer
    c.Data["perm"] = casbin.CasbinJsGetPermissionForUser(e, visitor)
    // Pass the data to the frontend.
    c.ServeJSON()
}
Notiz

Derzeit ist CasbinJsGetPermissionForUser nur in Go Casbin und Node-Casbin verfügbar. Um Unterstützung für andere Sprachen anzufordern, öffnen Sie bitte ein Issue oder hinterlassen Sie unten einen Kommentar.

API-Referenz​

setPermission(permission: string)​

Legt das Berechtigungsobjekt fest. Wird hauptsächlich im Modus manual verwendet.

setUser(user: string)​

Legt die Identität des Besuchers fest und aktualisiert die Berechtigungen. Wird hauptsächlich im Modus auto verwendet.

can(action: string, object: string)​

Prüft, ob der Benutzer die action am object ausführen kann.

cannot(action: string, object: string)​

Prüft, ob der Benutzer die action am object nicht ausführen kann.

canAll(action: string, objects: Array<object>)​

Prüft, ob der Benutzer die action auf allen Objekten in objects ausführen kann.

canAny(action: string, objects: Array<object>)​

Prüft, ob der Benutzer die action auf irgendeinem Objekt in objects ausführen kann.

Warum Casbin.js?​

Oft wird nach dem Unterschied zwischen Node-Casbin und Casbin.js gefragt. Node-Casbin ist die Kernimplementierung von Casbin für Node.js-Umgebungen und wird typischerweise auf Serverebene für die Verwaltung der Zugriffssteuerung eingesetzt. Casbin.js ist eine Frontend-Bibliothek, mit der Sie Casbin-Autorisierungslogik clientseitig für Webbenutzer anwenden können.

Das direkte Erstellen eines Casbin-Dienstes für die Frontend-Autorisierung birgt mehrere Probleme:

  1. Wenn ein Client eine Verbindung herstellt, initialisiert sich der Enforcer und ruft alle Richtlinien aus dem Backend-Speicher ab. Hohe Parallelität kann Datenbanken belasten und erhebliche Netzwerkbandbreite verbrauchen.
  2. Das Offenlegen aller Richtlinien gegenüber Clients erzeugt Sicherheitslücken.
  3. Eine enge Kopplung zwischen Client und Server erschwert Entwicklung und Wartung.

Casbin.js adressiert diese Herausforderungen durch die Verwaltung von Benutzerberechtigungen auf Client-Ebene. Die Kernfunktionalität besteht darin, die Berechtigungen des aktuellen Benutzers über einen Fetch-Vorgang mit dem Backend-Casbin-Dienst zu synchronisieren. Sobald die Berechtigungsdaten abgerufen wurden, können Entwickler Casbin.js-Schnittstellen nutzen, um das Benutzerverhalten im Frontend zu steuern.

Dieser Ansatz eliminiert wiederholte Enforcer-Initialisierungen, reduziert die Nachrichtengröße zwischen Client und Server und vermeidet die Offenlegung aller Richtlinien im Frontend. Benutzer greifen nur auf ihre eigenen Berechtigungen zu, ohne Kenntnis des Zugriffssteuerungsmodells oder der Berechtigungen anderer Benutzer. Darüber hinaus entkoppelt Casbin.js die Autorisierungslogik von Client und Server effektiv.
