ABAC in Go

Rollenbasierte Zugriffssteuerung beantwortet die Frage "Was darf ein Redakteur tun?". Viele reale Regeln benötigen mehr als nur eine Rolle: Autoren dürfen ihre eigenen Entwürfe bearbeiten, Redakteure dürfen Artikel aus ihrer eigenen Abteilung bearbeiten, jeder darf einen veröffentlichten Artikel lesen. Diese hängen von Attributen des Nutzers und der Ressource ab, dafür ist die attributbasierte Zugriffssteuerung (ABAC) gedacht.

Dieses Tutorial baut eine kleine Artikel-API in Go mit dem Standardpaket net/http auf und legt alle diese Regeln in einer Casbin-Policy-Datei fest. Dasselbe Modell und dieselbe Policy funktionieren unverändert in den Node.js- und Python-Versionen dieses Tutorials. Wenn Sie sich noch zwischen RBAC und ABAC entscheiden müssen, lesen Sie zuerst Auswahl eines Zugriffssteuerungsmodells.

1. Installation​

Go 1.22 oder neuer wird für die Methoden- und Wildcard-Muster in http.ServeMux benötigt.

go mod init example.com/abac
go get github.com/casbin/casbin/v3

2. Das Modell schreiben​

Speichern Sie dies als model.conf:

[request_definition]
r = sub, obj, act

[policy_definition]
p = sub_rule, obj_type, act

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = r.obj.Type == p.obj_type && r.act == p.act && eval(p.sub_rule)
  • r.sub und r.obj sind hier keine Strings, sondern Go-Strukturen. Der Matcher liest deren Felder, wie z. B. r.obj.Type.
  • Jede Policy-Regel trägt eine Bedingung in sub_rule. eval(p.sub_rule) wertet diese Bedingung gegen die Anfrage aus, sodass die Regeln in der Policy liegen und nicht im Modell.

3. Die Policy schreiben​

Speichern Sie dies als policy.csv:

p, r.obj.Status == 'published', article, read
p, r.sub.Name == r.obj.Owner, article, read
p, r.sub.Name == r.obj.Owner && r.obj.Status == 'draft', article, update
p, r.sub.Role == 'editor' && r.sub.Department == r.obj.Department, article, update
p, r.sub.Role == 'editor' && r.sub.Department == r.obj.Department, article, publish

Lesen Sie jede Zeile als "Erlaube diese Aktion für Artikel, wenn die Bedingung wahr ist":

  1. Jeder darf einen veröffentlichten Artikel lesen.
  2. Autoren dürfen ihre eigenen Artikel lesen, einschließlich Entwürfen.
  3. Autoren dürfen ihre eigenen Artikel bearbeiten, solange sie Entwürfe sind.
  4. Redakteure dürfen jeden Artikel aus ihrer eigenen Abteilung bearbeiten.
  5. Redakteure dürfen Artikel aus ihrer eigenen Abteilung veröffentlichen.
Tipp

Schreiben Sie String-Literale in Bedingungen mit einfachen Anführungszeichen, wie in 'published'. Ein doppeltes Anführungszeichen mitten in einem Feld bricht das CSV-Parsing. Wenn eine Bedingung ein Komma benötigt, setzen Sie das gesamte Feld in doppelte Anführungszeichen.

4. Den Server schreiben​

ABAC benötigt die Ressource selbst, nicht nur ihre URL, daher läuft die Prüfung erst, nachdem der Artikel geladen wurde. Der authorize-Helper erledigt dies und schreibt die Fehlerantwort, wenn die Antwort nein lautet.

main.go
package main

import (
    "encoding/json"
    "log"
    "net/http"
    "sync"

    "github.com/casbin/casbin/v3"
)

type User struct {
    Name       string
    Role       string
    Department string
}

type Article struct {
    ID         string `json:"id"`
    Type       string `json:"-"`
    Title      string `json:"title"`
    Owner      string `json:"owner"`
    Department string `json:"department"`
    Status     string `json:"status"`
}

// In a real application these come from your database.
var users = map[string]User{
    "alice": {Name: "alice", Role: "author", Department: "engineering"},
    "bob":   {Name: "bob", Role: "editor", Department: "engineering"},
    "carol": {Name: "carol", Role: "editor", Department: "sales"},
    "dave":  {Name: "dave", Role: "author", Department: "engineering"},
}

var (
    mu       sync.Mutex
    articles = map[string]*Article{
        "1": {ID: "1", Type: "article", Title: "Draft by alice", Owner: "alice", Department: "engineering", Status: "draft"},
        "2": {ID: "2", Type: "article", Title: "Published by alice", Owner: "alice", Department: "engineering", Status: "published"},
    }
)

type server struct {
    e *casbin.Enforcer
}

// authorize loads the current user and asks Casbin whether they may perform act on the article.
func (s *server) authorize(w http.ResponseWriter, r *http.Request, a *Article, act string) bool {
    // Replace this with the user from your session or JWT.
    user, ok := users[r.Header.Get("X-User")]
    if !ok {
        http.Error(w, "unauthenticated", http.StatusUnauthorized)
        return false
    }
    allowed, err := s.e.Enforce(user, *a, act)
    if err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return false
    }
    if !allowed {
        http.Error(w, "forbidden", http.StatusForbidden)
        return false
    }
    return true
}

func (s *server) article(w http.ResponseWriter, r *http.Request) *Article {
    mu.Lock()
    defer mu.Unlock()
    a, ok := articles[r.PathValue("id")]
    if !ok {
        http.NotFound(w, r)
        return nil
    }
    return a
}

func main() {
    e, err := casbin.NewEnforcer("model.conf", "policy.csv")
    if err != nil {
        log.Fatal(err)
    }
    s := &server{e: e}

    mux := http.NewServeMux()
    mux.HandleFunc("GET /articles/{id}", func(w http.ResponseWriter, r *http.Request) {
        a := s.article(w, r)
        if a == nil || !s.authorize(w, r, a, "read") {
            return
        }
        json.NewEncoder(w).Encode(a)
    })
    mux.HandleFunc("PUT /articles/{id}", func(w http.ResponseWriter, r *http.Request) {
        a := s.article(w, r)
        if a == nil || !s.authorize(w, r, a, "update") {
            return
        }
        mu.Lock()
        json.NewDecoder(r.Body).Decode(&struct {
            Title *string `json:"title"`
        }{&a.Title})
        mu.Unlock()
        json.NewEncoder(w).Encode(a)
    })
    mux.HandleFunc("POST /articles/{id}/publish", func(w http.ResponseWriter, r *http.Request) {
        a := s.article(w, r)
        if a == nil || !s.authorize(w, r, a, "publish") {
            return
        }
        mu.Lock()
        a.Status = "published"
        mu.Unlock()
        json.NewEncoder(w).Encode(a)
    })

    log.Fatal(http.ListenAndServe(":8080", mux))
}

Casbin liest Struktur-Felder über Reflection, daher müssen die in der Policy verwendeten Felder (Name, Owner, Status usw.) exportiert sein.

Notiz

Der X-User-Header hält das Beispiel kurz. Casbin übernimmt nur die Autorisierung; in einer realen Anwendung kommt der Nutzer aus Ihrer Authentifizierungsschicht, wie z. B. einem verifizierten JWT oder einer Session.

5. Testen Sie es​

go run .

Artikel 1 ist Alices Entwurf und Artikel 2 ist ihr veröffentlichter Artikel, beide in der Engineering-Abteilung.

curl -i -H "X-User: dave"  http://localhost:8080/articles/1                 # 403, someone else's draft
curl -i -H "X-User: dave"  http://localhost:8080/articles/2                 # 200, published
curl -i -X PUT -H "X-User: alice" -d '{"title":"New title"}' \
     http://localhost:8080/articles/1                                       # 200, her own draft
curl -i -X PUT -H "X-User: alice" -d '{"title":"x"}' \
     http://localhost:8080/articles/2                                       # 403, no longer a draft
curl -i -X PUT -H "X-User: bob"   -d '{"title":"x"}' \
     http://localhost:8080/articles/2                                       # 200, editor in engineering
curl -i -X PUT -H "X-User: carol" -d '{"title":"x"}' \
     http://localhost:8080/articles/2                                       # 403, editor in sales
curl -i -X POST -H "X-User: alice" http://localhost:8080/articles/1/publish # 403, authors cannot publish
curl -i -X POST -H "X-User: bob"   http://localhost:8080/articles/1/publish # 200
curl -i -H "X-User: dave"  http://localhost:8080/articles/1                 # 200, now published

6. Regeln zur Laufzeit ändern​

Bedingungen sind Policy-Zeilen, sie können also hinzugefügt und entfernt werden, während der Server läuft, und über einen Adapter in einer Datenbank gespeichert werden:

// Admins may edit any article.
e.AddPolicy("r.sub.Role == 'admin'", "article", "update")

// Nobody may publish any more.
e.RemoveFilteredPolicy(1, "article", "publish")

Um herauszufinden, welche Regel eine Anfrage erlaubt hat, verwenden Sie EnforceEx. Es gibt die übereinstimmende Regel zurück, was für Audit-Logs nützlich ist:

ok, rule, _ := e.EnforceEx(users["bob"], *articles["2"], "update")
// true [r.sub.Role == 'editor' && r.sub.Department == r.obj.Department article update]

ABAC oder RBAC?​

  • Verwenden Sie RBAC, wenn Berechtigungen nach Funktionsbereichen festgelegt sind und nicht davon abhängen, auf welchen Datensatz zugegriffen wird. Es ist einfacher zu prüfen: "Liste alles auf, was ein Redakteur tun darf" ist eine einfache Abfrage. Siehe das RBAC-Tutorial in Go.
  • Verwenden Sie ABAC, wenn die Antwort vom Datensatz abhängt: seinem Besitzer, seiner Abteilung, seinem Status oder seiner Sensitivität.
  • Die meisten Anwendungen kombinieren beide Ansätze: Rollen entscheiden, welche Funktionen ein Nutzer erreichen kann, und Attribute schränken dies auf die Datensätze ein, auf die er zugreifen darf. Der Vergleich der Zugriffssteuerungsmodelle zeigt ein kombiniertes Modell.

Nächste Schritte​

  • Vollständige ABAC-Referenz. ABAC behandelt JSON-Anfrageparameter, Anführungszeichenregeln und eval() im Detail.
  • Regeln für Zeit und Ort. Fügen Sie weitere Anfragefelder hinzu, z. B. eine IP-Adresse, die mit ipMatch geprüft wird, oder die aktuelle Zeit als Attribut übergeben. Siehe Functions.
  • Deny-Regeln. Fügen Sie eine eft-Spalte hinzu und verwenden Sie einen Deny-Override-Effekt, damit eine Regel blockieren kann, was andere erlauben. Siehe Effector.
  • Experimentieren Sie im Browser. Der Online-Editor kann ABAC-Anfragen mit JSON-Attributen auswerten.
