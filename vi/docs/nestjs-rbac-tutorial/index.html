NestJS RBAC Tutorial: Role-Based Access Control with Guards

Hướng dẫn này thêm kiểm soát truy cập dựa trên vai trò (RBAC) vào một API NestJS với node-casbin. Mỗi route khai báo quyền mà nó cần bằng một decorator, một global guard hỏi Casbin xem người dùng hiện tại có quyền đó hay không, và các vai trò kế thừa lẫn nhau, do đó một admin tự động nhận được mọi thứ mà một editor có thể làm.

Các quyền được đặt tên theo tài nguyên và hành động (articles, delete) thay vì đường dẫn URL, điều này phù hợp tốt với các controller NestJS. Đối với các quy tắc dựa trên đường dẫn, hãy xem phiên bản Express.

1. Cài đặt​

Bắt đầu từ một dự án NestJS (nest new my-app) và thêm Casbin:

npm install casbin

2. Viết model​

Lưu tệp này dưới tên model.conf trong thư mục gốc của dự án:

[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[role_definition]
g = _, _

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = g(r.sub, p.sub) && r.obj == p.obj && r.act == p.act
  • r = sub, obj, act: mỗi yêu cầu gồm một người dùng, một tài nguyên và một hành động.
  • g = _, _: người dùng có thể được gán cho các vai trò, và các vai trò có thể được gán cho các vai trò khác.
  • g(r.sub, p.sub) đúng khi người dùng có vai trò trong quy tắc policy, trực tiếp hoặc thông qua các vai trò kế thừa.

3. Viết policy​

Lưu tệp này dưới tên policy.csv:

p, viewer, articles, read
p, editor, articles, create
p, editor, articles, update
p, admin, articles, delete

g, editor, viewer
g, admin, editor

g, alice, admin
g, bob, editor
g, carol, viewer

Khối đầu tiên cấp cho mỗi vai trò chỉ những quyền mới ở cấp độ đó. Khối thứ hai xây dựng phân cấp: một editor cũng là một viewer, và một admin cũng là một editor. Khối cuối cùng gán người dùng cho các vai trò. Kết quả là:

UserRolereadcreateupdatedelete
aliceadminyesyesyesyes
bobeditoryesyesyesno
carolvieweryesnonono
dave(none)nononono

4. Thêm một permission decorator​

src/permission.decorator.ts
import { SetMetadata } from '@nestjs/common';

export const PERMISSION_KEY = 'permission';

export interface Permission {
  resource: string;
  action: string;
}

// Declares which permission a route needs, for example @RequirePermission('articles', 'delete').
export const RequirePermission = (resource: string, action: string) =>
  SetMetadata(PERMISSION_KEY, { resource, action } as Permission);

5. Thêm guard​

Guard đọc permission từ metadata của route và hỏi Casbin. Các route không có decorator vẫn là công khai.

src/casbin.guard.ts
import { CanActivate, ExecutionContext, ForbiddenException, Inject, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Enforcer } from 'casbin';
import { Request } from 'express';
import { Permission, PERMISSION_KEY } from './permission.decorator';

export const ENFORCER = 'CASBIN_ENFORCER';

@Injectable()
export class CasbinGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    @Inject(ENFORCER) private readonly enforcer: Enforcer,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const permission = this.reflector.getAllAndOverride<Permission>(PERMISSION_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!permission) {
      return true; // Routes without @RequirePermission are public.
    }

    const request = context.switchToHttp().getRequest<Request>();
    // Replace this with the user your authentication guard puts on the request, such as request.user.
    const user = request.header('X-User') ?? '';

    const allowed = await this.enforcer.enforce(user, permission.resource, permission.action);
    if (!allowed) {
      throw new ForbiddenException();
    }
    return true;
  }
}
ghi chú

Header X-User giúp ví dụ ngắn gọn. Casbin chỉ xử lý ủy quyền (authorization). Trong ứng dụng thực tế, một authentication guard, chẳng hạn như dựa trên @nestjs/passport, sẽ chạy trước và đặt request.user; hãy đọc tên người dùng hoặc ID từ đó.

6. Sử dụng trong controller​

src/articles.controller.ts
import { Controller, Delete, Get, Param, Post, Put } from '@nestjs/common';
import { RequirePermission } from './permission.decorator';

@Controller('articles')
export class ArticlesController {
  @Get()
  @RequirePermission('articles', 'read')
  findAll() {
    return { articles: [] };
  }

  @Post()
  @RequirePermission('articles', 'create')
  create() {
    return { created: true };
  }

  @Put(':id')
  @RequirePermission('articles', 'update')
  update(@Param('id') id: string) {
    return { updated: id };
  }

  @Delete(':id')
  @RequirePermission('articles', 'delete')
  remove(@Param('id') id: string) {
    return { deleted: id };
  }
}

7. Đăng ký enforcer và guard​

Enforcer được tạo một lần bởi một factory provider và được inject vào guard. Việc đăng ký guard với APP_GUARD áp dụng nó cho mọi route trong ứng dụng.

src/app.module.ts
import { Module } from '@nestjs/common';
import { APP_GUARD } from '@nestjs/core';
import { newEnforcer } from 'casbin';
import { ArticlesController } from './articles.controller';
import { CasbinGuard, ENFORCER } from './casbin.guard';

@Module({
  controllers: [ArticlesController],
  providers: [
    {
      provide: ENFORCER,
      useFactory: () => newEnforcer('model.conf', 'policy.csv'),
    },
    {
      provide: APP_GUARD,
      useClass: CasbinGuard,
    },
  ],
})
export class AppModule {}

8. Thử nghiệm​

npm run start
curl -i -X DELETE -H "X-User: alice" http://localhost:3000/articles/1   # 200, admins can delete
curl -i -X DELETE -H "X-User: bob"   http://localhost:3000/articles/1   # 403, editors cannot
curl -i -X PUT    -H "X-User: bob"   http://localhost:3000/articles/1   # 200, editors can update
curl -i -X POST   -H "X-User: carol" http://localhost:3000/articles     # 403, viewers are read-only
curl -i           -H "X-User: carol" http://localhost:3000/articles     # 200
curl -i           -H "X-User: dave"  http://localhost:3000/articles     # 403, no role

9. Quản lý vai trò tại runtime​

Inject enforcer bất kỳ nơi nào bạn cần, ví dụ trong một admin service, bằng @Inject(ENFORCER):

await enforcer.addRoleForUser('dave', 'editor');          // dave becomes an editor
await enforcer.getImplicitRolesForUser('alice');          // [ 'admin', 'editor', 'viewer' ]
await enforcer.getImplicitPermissionsForUser('bob');
// [ [ 'editor', 'articles', 'create' ], [ 'editor', 'articles', 'update' ], [ 'viewer', 'articles', 'read' ] ]

getImplicitPermissionsForUser hữu ích cho một endpoint "tôi có thể làm gì" mà frontend sử dụng để hiển thị hoặc ẩn các nút. Danh sách đầy đủ có trong RBAC API.

Các bước tiếp theo​

  • Lưu trữ policy trong cơ sở dữ liệu. Thay thế policy.csv bằng một adapter, ví dụ TypeORM, Prisma, Sequelize hoặc MongoDB. Những thay đổi policy được thực hiện qua API sau đó sẽ được lưu tự động.
  • Nhiều instance. Sử dụng một watcher để mỗi instance tải lại policy khi một trong số chúng thay đổi nó.
  • Quy tắc sở hữu. "Tác giả chỉ có thể chỉnh sửa bài viết của chính họ" phụ thuộc vào bài viết, không chỉ vai trò. Tải bài viết trong handler và kiểm tra nó với mô hình ABAC.
  • Ứng dụng đa thuê bao (multi-tenant). RBAC với domains cung cấp cho một người dùng các vai trò khác nhau trong các tenant khác nhau; thêm tenant làm đối số thứ tư cho enforce.
  • Các module có sẵn. Danh sách middleware liên kết đến các module NestJS cộng đồng như nest-authz.

Điều khoản dịch vụ

Apache Casbin (Incubating) là một dự án đang trong quá trình ươm tạo tại The Apache Software Foundation (ASF), được tài trợ bởi Apache Incubator. Việc ươm tạo là bắt buộc đối với tất cả các dự án mới được chấp nhận cho đến khi có đánh giá thêm rằng cơ sở hạ tầng, giao tiếp và quy trình ra quyết định đã ổn định theo cách nhất quán với các dự án ASF thành công khác. Mặc dù trạng thái ươm tạo không nhất thiết phản ánh sự hoàn thiện hoặc tính ổn định của mã nguồn, nhưng nó cho thấy dự án chưa được ASF chính thức bảo trợ hoàn toàn.
