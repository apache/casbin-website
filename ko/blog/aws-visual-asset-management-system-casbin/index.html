AWS가 시각적 자산 관리 시스템에서 Apache Casbin을 사용하는 방법

2026년 11월 1일 · 약 3분
Yang Luo
Creator of Casbin

AWS Visual Asset Management System (VAMS)는 물리적 AI를 위한 시각적 자산 관리 및 배포를 담당하는 AWS의 오픈소스 플랫폼입니다. AWS가 VAMS 2.0을 출시했을 때 Cognito 그룹을 Casbin 기반 ABAC/RBAC 권한 시스템으로 교체했습니다. 최근 발표된 2.6 릴리스는 동일한 설계를 유지하며 그 위에 중앙 집중식 API 인가자를 추가했습니다.

두 단계, 하나의 Enforcer​

VAMS는 모든 API 요청을 두 개의 독립적인 단계에 대해 검사합니다. Tier 1은 사용자의 역할이 엔드포인트를 호출할 수 있는지 결정하며, HTTP 메서드를 라우트 경로와 비교합니다. Tier 2는 해당 역할이 특정 객체에 대해 작업을 수행할 수 있는지 결정하며, 메서드를 databaseId, assetName, tags와 같은 엔티티 속성과 비교합니다. 두 단계 모두 요청을 허용해야 합니다. 하나라도 거부되면 호출이 거부됩니다.

백엔드는 pycasbin을 사용합니다. 각 사용자는 메모리 내 모델과 문자열 어댑터로 구성된 FastEnforcer를 감싸는 CasbinEnforcer를 받습니다. 정책은 DynamoDB에 저장된 사용자의 역할과 제약 조건에서 런타임에 조립되며 사용자별로 60초 동안 캐시됩니다. 정책을 가져올 수 없는 경우, Enforcer는 실패 개방(fail open) 대신 모두 거부(deny-all) 정책으로 폴백합니다.

모델의 matcher는 g(r.sub, p.sub) && eval(p.obj_rule) && r.act == p.act이므로, 역할의 제약 조건은 리소스와 작업에 대한 객체 수준 표현식을 포함할 수 있습니다. Casbin의 역할 링크는 사용자-역할 매핑을 처리하며, 제약 조건은 ABAC 부분을 제공합니다.

2.6에서의 변경 사항​

2.6 릴리스는 API 계층을 위한 단일 중앙 집중식 인가자를 추가하여 이전에 개별 핸들러에 있던 다중 요소 및 클레임 로직을 통합했습니다. 또한 고급 AWS IAM 역할 맞춤화와 Cognito OIDC 연동을 추가했습니다. 권한 부여 모델 자체는 변경되지 않았습니다. Casbin은 여전히 두 단계를 평가하며, 커스텀 Lambda 인가자를 통해 IP 제한을 추가로 적용할 수 있습니다.

VAMS 문서는 전체 모델, 객체 유형 및 제약 조건 필드를 Permissions Model에서 설명합니다. Enforcer 구현은 authz 모듈에 있습니다.
