Casbin (Go) v2 から v3 へのアップグレード: 完全な移行ガイド

2026年2月1日 · 1分読む
Yang Luo
Creator of Casbin

本番環境で Casbin v2 を実行しており、v3 へのアップグレードパスについて疑問がある場合、このガイドはあなたのためです。変更点の理解から安全な本番移行の実行まで、移行に必要なすべての情報を網羅します。

What Changed in v3?​

良いニュース: v3 は主にモジュールパスの変更であり、完全な後方互換性を維持しています。コアの認可ロジック、API、機能は変更されていません。これは Go のセマンティックバージョニング規約に従いながら、混乱を最小限に抑えるための意図的な決定でした。

The Main Change: Module Path​

v3 における唯一の破壊的変更は、Go モジュールパスです:

// v2
import "github.com/casbin/casbin/v2"

// v3
import "github.com/casbin/casbin/v3"

以上です。既存のポリシー、モデル、コードロジックを変更する必要はありません。移行は機械的です: import ステートメントと go.mod ファイルを更新してください。

Why Release v3?​

なぜ import パスの変更だけで新しいメジャーバージョンをリリースするのか疑問に思うかもしれません。答えはセマンティックバージョニングにあります。Go のモジュールシステムでは、import パスにメジャーバージョン番号 (/v2, /v3 など) が含まれます。これにより、同じ依存関係ツリー内で複数のメジャーバージョンが共存できるようになり、多くの依存関係を持つ大規模アプリケーションにとって不可欠です。

v3 をリリースすることで、私たちは以下を行いました:

  • Go のセマンティックインポートバージョニングに準拠
  • 複雑な依存関係グラフでの段階的な移行を可能にする
  • 既存の v2 ユーザーを壊すことなく、将来の強化のための基盤を整える

What Stayed the Same?​

その他すべてです。本当に。

  • すべての API は同一のままです - Enforce(), AddPolicy(), GetAllRoles() およびその他のすべてのメソッドは以前と完全に同じように動作します
  • モデルとポリシーの構文は変更なし - 既存の .conf モデルファイルと .csv ポリシーファイルは修正なしで動作します
  • アダプターインターフェースは変更なし - persist.Adapter メソッドは同じです; アダプターは v3 モジュールパスに対してビルドされたリリースのみが必要です
  • パフォーマンス特性 - パフォーマンスの低下や向上はありません; エンジンは同じです
  • ミドルウェア統合 - ミドルウェアは、エンフォーサーと同じメジャーバージョンをインポートすれば、同じように動作します

New Features in v3​

2025年12月の v3.0.0 リリース以来、いくつかの新機能が追加されました:

v3.7.0+: Enhanced Logger Integration​

カスタムロガーを Casbin のコア認可およびポリシー管理操作に統合できるようになり、可観測性が向上しました:

enforcer.SetLogger(yourCustomLogger)

v3.8.0+: GetAllUsers() API​

ユーザーとロールを区別するための新しい API:

users, err := enforcer.GetAllUsers()

これは、ロール定義から実際のユーザーを個別にリストアップする必要がある RBAC システムで特に有用です。

v3.9.0+: Built-in Cycle Detection​

エンフォーサーには、無限ループを防ぐためのロール階層内のサイクル自動検出機能が組み込まれています:

// Automatically detects and prevents circular role assignments
enforcer.AddGroupingPolicy("alice", "admin")
enforcer.AddGroupingPolicy("admin", "alice") // Will be detected as a cycle

v3.10.0+: Explain() API for AI-Powered Authorization Insights​

最新の機能は LLM API を活用し、自然言語で認可決定を説明します:

enforcer.SetAIConfig(casbin.AIConfig{
    Endpoint: "https://api.openai.com/v1/chat/completions",
    APIKey:   os.Getenv("OPENAI_API_KEY"),
    Model:    "gpt-4",
})

explanation, err := enforcer.Explain("alice", "data1", "read")
// e.g. "Alice can read data1 because she has the 'reader' role..."

これは、複雑なポリシーのデバッグや、非技術者ステークホルダーが認可決定を理解する助けとして特に価値があります。

移行戦略​

新規プロジェクトの場合​

シンプルに、最初から v3 を使用してください。

go get github.com/casbin/casbin/v3
import "github.com/casbin/casbin/v3"

既存の v2 プロジェクトの場合​

移行には以下の 3 ステップが含まれます:

ステップ 1: go.mod の更新​

go get github.com/casbin/casbin/v3
go mod tidy

ステップ 2: インポートステートメントの更新​

コードベース全体で Casbin のインポートを検索し、置き換えてください:

# Using sed on Unix/Linux/Mac
find . -type f -name '*.go' -exec sed -i 's|github.com/casbin/casbin/v2|github.com/casbin/casbin/v3|g' {} +

# Or manually in your editor
# Find: github.com/casbin/casbin/v2
# Replace: github.com/casbin/casbin/v3

ステップ 3: アダプターインポートの更新 (該当する場合)​

アダプターは特定のメジャーバージョンから persist.Adapter を実装します。これは、casbin/v2 と casbin/v3 で model.Model が異なる Go の型だからです。したがって、v3 のエンフォーサーには github.com/casbin/casbin/v3 をインポートしているアダプターのリリースが必要です。アダプターの go.mod を確認してください:

// Example: the PostgreSQL adapter already depends on casbin/v3
import pgadapter "github.com/apache/casbin-pg-adapter"

// The file adapter is built in and ships with each major version

アダプターがまだ更新されていない場合は、更新されるまでそのサービスでは v2 のままにするか、アダプターのリポジトリで issue を作成してください。

ロールバック計画​

ロールバックが必要な場合:

  1. コードレベル: インポートの変更を元に戻す (バージョン管理を使用)
  2. 依存関係レベル: go get github.com/casbin/casbin/v2@latest
  3. デプロイ: 標準的なデプロイプロセスを使用して元に戻す

この移行の利点は、ロールバックが非常に簡単であることです。インポートの変更を元に戻して再デプロイするだけです。

ポリシーデータベースを移行する必要がありますか?​

いいえ。 既存のポリシーデータは変更されません。ポリシーは単純な文字列 (subject, object, action など) として保存されており、Casbin のバージョンに依存しません。

移行のテスト​

自動テスト​

既存のテストは修正なしでパスするはずです:

func TestPolicyEnforcement(t *testing.T) {
    // This test works identically in v2 and v3
    e, _ := casbin.NewEnforcer("model.conf", "policy.csv")
    
    ok, _ := e.Enforce("alice", "data1", "read")
    if !ok {
        t.Error("Expected alice to have read access to data1")
    }
}

統合テスト​

*casbin.Enforcer を受け取るミドルウェアは、アダプターと同様に 1 つのメジャーバージョンに紐付けられています。ミドルウェアがまだ casbin/v2 をインポートしている場合、エンフォーサーを直接呼び出すのは数行で済みます:

// Example with Gin
import (
    "net/http"

    "github.com/casbin/casbin/v3"
    "github.com/gin-gonic/gin"
)

func Authorizer(e *casbin.Enforcer) gin.HandlerFunc {
    return func(c *gin.Context) {
        ok, err := e.Enforce(c.GetString("user"), c.Request.URL.Path, c.Request.Method)
        if err != nil || !ok {
            c.AbortWithStatus(http.StatusForbidden)
            return
        }
        c.Next()
    }
}

負荷テスト​

v3 ビルドに対して標準的な負荷テストを実行してください。パフォーマンス特性は v2 と同一であるはずです。

ポリシー検証​

バージョン間でのポリシー評価を比較してください:

# Export policies from v2
# Load into v3
# Run test cases against both
# Compare results

差異が見られた場合は、バグの可能性が高いので報告してください!

よくある落とし穴​

落とし穴 1: v2/v3 依存関係の混在​

問題: 一部の依存関係が Casbin v2 を使用し、他が v3 を使用しており、競合が発生しています。

解決策: ビルド自体は問題ありません。Go のモジュールシステムは v2 と v3 を別個のパッケージとして扱うため、同じ依存ツリー内に共存できます。できないのは、v2 を期待するライブラリに v3 のエンフォーサーを渡すことです。エンフォーサー、そのアダプター、およびそのミドルウェアを同じメジャーバージョンに保ってください。

落とし穴 2: アダプターバージョンの不一致​

問題: Casbin v3 で v2 アダプターを使用している (またはその逆)。

解決策: これはランタイムの予期しない動作ではなく、コンパイルエラーとして現れます。アダプターの go.mod がどの Casbin メジャーバージョンを要求しているかを確認し、エンフォーサーと一致するリリースを使用してください。

落とし穴 3: 内部パッケージの忘れ​

問題: メインアプリケーションのインポートは更新したが、内部パッケージやツールを忘れた。

解決策: すべての Casbin 依存関係を見つけるために go mod graph と go mod why を使用してください:

go mod graph | grep casbin

落とし穴 4: カスタムアダプターのコンパイル問題​

問題: アップグレード後にカスタムアダプターがコンパイルされません。

解決策: アダプターインターフェースは変更されていないため、これはインポートの問題を示唆しています。アダプター内のすべての Casbin インポートが v3 を使用しているか確認してください:

import (
    "github.com/casbin/casbin/v3"
    "github.com/casbin/casbin/v3/persist"
)

FAQ​

Q: v2 はまだメンテナンスされていますか?​

執筆時点では、v2 は重大なバグ修正を受け取っていますが、新機能は v3 で開発されています。今後 6〜12 か月以内に移行する計画を立ててください。

Q: 一部のサービスを v2 に、他のサービスを v3 に置いて段階的に移行できますか?​

はい! 同じポリシーデータベースを共有することも可能です。これは v3 の変更が最小限であることの利点の 1 つです。

Q: 私のミドルウェア (Gin, Echo, Fiber など) は動作しますか?​

同じメジャーバージョンを enforcer とインポートしている場合のみ動作します。ミドルウェアの go.mod を確認し、まだ v2 の場合は、上記のように独自の小さなハンドラーから Enforce() を呼び出してください。

Q: .conf モデルファイルを更新する必要がありますか?​

いいえ。モデルファイルの構文は変更されていません。

Q: .csv ポリシーファイルを更新する必要がありますか?​

いいえ。ポリシーファイル形式は変更されていません。

Q: WatcherEx, FilteredAdapter, その他のインターフェースはどうなりますか?​

すべてのインターフェースは変更されていません。これらのインターフェースを実装しているコードがあれば、(インポートパスを除いて) 修正は不要です。

Q: パフォーマンスへの影響は?​

ありません。v3 は v2 と同じ評価エンジンを使用しています。

Q: Go 1.16 で v3 を使用できますか?​

Casbin v3 リポジトリの go.mod でサポートされる最小 Go バージョンを確認してください。一般的には、最新の安定版 Go バージョンの使用が推奨されます。

アップグレードをお楽しみください!
